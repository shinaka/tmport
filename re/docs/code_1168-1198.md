# TMTWINCD.EXE code segments 1168–1198

Scope: NE code segments 46–52 of `TMTWINCD.EXE` (Ghidra selectors `1168`, `1170`, `1178`, `1180`,
`1188`, `1190`, `1198`). The source is the Ghidra export in `re\win\ghidra_export\` (decompiled
`functions\SSSS_OOOO.c`, `disassembly.asm`). I also parsed the NE segment and relocation tables
myself to find code that Ghidra did not turn into functions, and to resolve far-pointer tables in
DGROUP. Values from DGROUP were read straight from the EXE, where `DGROUP:XXXX` is at file offset
`0x23c00 + XXXX`. Resources were read from `extracted\res\…`. The scratch scripts are in
`extracted\scratch\code_1168\` (`dg.py`, `nerel.py`, `bndl.py`, `rooms.py`, `pm16.py`, `t1-3.py`),
`extracted\scratch\verify_1168\` and `extracted\scratch\code_1168_v2\` (`rel56.py` resolves the
far-pointer relocations of any segment, including DGROUP; `strip.py` renders PMAPs with
`tools\assets\pmap.py`).

Names of functions and globals owned by **other** modules follow those modules' names files
(`re\names\*.tsv`) where they exist; §1 lists both the owner's name and the short alias used in
this document.

Labels used throughout:
**[O]** = observed (seen directly in the bytes, decompiled code or disassembly).
**[I]** = inferred (my interpretation of the purpose or meaning).
Addresses are `selector:offset`. A DGROUP global is written `DAT_XXXX`, or `g_name (DGROUP:XXXX)`.

General findings for all seven segments **[O]**:
- **No C++ classes.** There are no constructors, destructors, vtables or `this` pointers. Every
  function is a plain `far __cdecl` C function that works on DGROUP globals. The only indirect
  calls go through a far function-pointer table in DGROUP (`2c8f`, elf behaviours) and through the
  Help-menu handler table (`12fd`).
- **Every function is far** (`inc bp; push bp; mov bp,sp … dec bp; retf`; the Help stubs at
  `1180:0117..014a` and `1170:0082` have no prologue but also end in `retf`), including the ones only
  called from inside their own segment (`1178:0565`, `1178:0766`, `1180:0000`, `1188:01aa`, …).
  Borland calls those with `PUSH CS; CALL near` (e.g. `1178:0a86-0a87`, `1188:008f-0090`), so the
  decompiler shows the pushed CS as an extra first parameter. A port can treat them as ordinary
  functions.
- **No Borland RTL code** lives in these segments. They call two RTL routines from segment 1000:
  `rand()` = `1000:0859` (Borland LCG, returns 0..0x7fff) and `SCOPY@` = `1000:02f7` (struct copy,
  byte count in CX).
- **No direct Windows API calls.** None of these segments has an import-relocation record. All
  Windows work goes through wrappers in other segments.
- Random numbers are always scaled as `rand()*N/0x8000`, which gives an integer 0..N-1.
  Below this is written `R(N)`.

Code that Ghidra did not turn into functions **[O]**:
- `1168:00b2-00b9`: the 4-entry `switch` jump table of `1168:0047`.
- `1170:0082`: a 6-byte function `CALLF 1088:0175; RETF` (named `Sfx_IsPlaying`). Nothing
  references it, so it is dead code.
- `1178:0e25-101e`: the body of `1178:0cb0` (switch cases 9–13). `1178:101f-103f` is its
  jump table.
- `1180:0105-0116`: the 9-entry jump table of a no-op `switch` in `1180:0000`.
- `1180:0117`, `0128`, `0139`, `014a`: four 17-byte prologue-less far functions, the Help topic
  entry points. They are referenced from DGROUP `12fd..1309` by relocation.
- `1198:06a6-06b3`: the 7-entry jump table of `1198:0527`.

### 1.1 Off-screen surface layers **[O]**

All drawing goes to one 512-pixel-wide off-screen surface. The same picture is kept at three
vertical offsets:

| y range | Name | Contents |
|---|---|---|
| 0x000–0x17f | **work/screen** | What is presented. The playfield is y 0x14..0x11e (512×267). The y=0x11f line plus 0x120..0x17f is the status bar. |
| +0x180 | **bg layer** | Clean room background, including slot objects and the net-shop sign. `Surf_Restore(…,0x180)` erases sprites from it. |
| +0x300 | **pristine layer** | The room background picture only, with no slot objects (written by `1198:0234`). |

A sprite is erased by restoring its rect from the layer below it. Drawing functions take a `yoff`
(0 or 0x180), so a whole room can be composed into the bg layer and then copied or dissolved onto
the screen.

## 2. Segment 1168: castle-wall ladder climb (room 0x31)

**Verified against the original (E7, per REFERENCE_CAPTURES §R3):** walking on screen 0 (including
the `dxLeft` quirk, M8), the clamps, climbing, jumps, falls, the landing frames, the screen layouts and
the wall creature match this section value by value.

### 2.1 Role **[O, story I]**

`1118:0000` (the main game loop) calls `ClimbScene_Run()` (`1168:0000`) when the current room is
0x31. That room is level 3, reached after the three mountain levels. When it returns, the main
loop sets the room to 0xfe ("finished") and then runs the ending/award sequence (`10f0:0000`).

What the player sees:
- **Screen 0** is the foot of the castle wall (background 1040, which has a doorway and a ladder
  painted in).
- The kid walks left and right and presses Up at a ladder to start climbing.
- **Screens 1–3** are plain wall (background 1041) with ladders drawn from one of four layouts.
- On screens 1–3 the kid can climb up and down, jump sideways between ladder columns, and fall
  when there is no ladder.
- The **Master of Mischief** (BNDL 326; the art shows the wizard in a stone window, reaching out
  further in each frame **[I: from the pictures]**) can appear in the wall on screens 1–3 and
  push the kid sideways off the ladder next to his window. Each push costs one coin. The code
  calls nothing else for him, so below he is "the creature" (`cl_creat*`).
- Climbing off the top of screen 3 completes the scene.

There is no other exit except Esc → quit dialog.

### 2.5 Scene flow

**`ClimbScene_Run` (1168:0000)** **[O]**
1. `Clip_SetPlayfield(0)`. Set creature tick, screen and done to 0.
2. Call `LoadResources`, then `PickLayout`, then `DrawScreenBackground`.
3. Set `cl_fadePending = 1` and `cl_fullPresent = 1`.
4. While not `cl_done`: call `WalkLoop()`, then `ClimbLoop()`.
5. Call `FreeResources()`.

The player's starting x, y and frame come from room 0x31's record (x=80, y=142), which the main
loop applies before the call.

**`PickLayout` (1168:0047)**: `cl_layout = DS:2950 + 40*R(g_rankTier+1)`. Tier 0 always gets layout
0. Higher tiers add the layouts with half ladders. **[O]**

**`DrawScreenBackground` (1168:0299)** **[O]**
1. Screen 0: `Bg_Load(1040)`. Otherwise `Bg_Load(1041)`.
2. `Pix_DrawOpaque(0,0x14)`.
3. If screen ≠ 0, for each column c, let `x = colX[c] − 29`:
   - `cell(s,c)==1`: draw the full ladder at (x, 20).
   - `cell==2`: draw the lower ladder at (x, 141).
   - Otherwise, if `cell(s−1,c)==1`: draw the stub at (x, 254). (The ladder from the screen below
     pokes up.)

   All three sprites end at y=287.
4. Colour 0, `HLine(0,0x11f,512)`.
5. `Surf_Copy(0,20,512,267 → 0,0x194)`: save the result as the bg layer.

**`FindLadderAtPlayer` (1168:03d6)** → 0/1 **[O]**

Look for the first column c (0..4) where both hold:
- `g_plX < colX[c] < g_plX + g_plW`, and
- `cell(screen,c)==1`, or `cell==2` and `g_plY > 0x55`.

If found: `cl_column = c` and return 1. Otherwise return 0.

### 2.6 Walking mode (screen 0)

**`WalkLoop` (1168:0442)** **[O]**
1. Register hotspots:
   - 0x600 (0,20,512,208): "steer"
   - 0x0d (0,228,512,59): releasing the left button inside it yields input code 0x000d, the same
     as the Enter key (so clicking the floor strip tosses a coin)
   - 0x601 (0,20,0,208): left edge
   - 0x602 (512,20,0,208): right edge
2. Reset the walking state:
   - `g_plFrame=0`, `g_plY=yForFrame[0]` (142), `g_plFacing=0`.
   - `g_plW/H` = frame-0 size of BNDL 300.
   - Clear `cl_done`, `cl_onLadder`, `g_auxFrame`, `g_plJumping`, `g_coinAnim`, `g_noNetAnim`,
     `g_netAnim`.
   - x is kept.
3. Each tick:
   1. `Timer_Set(7,100)`. `cl_input = Input_Get()`. If it is 0x1b, call `QuitDialog()`.
   2. `Clip_SetPlayfield(0)`, `DAT_0862 = 1`, `Dirty_Clear()`.
   3. Erase the aux sprite (`10e0:1057`) and the player (`10e0:042c`).
   4. Call `WalkUpdate()`.
   5. Draw the player (`10e0:0ff4(0)`: BNDL 300 frame `g_plFrame`, flip = facing). Draw the aux
      sprite (`10e0:1079(0)`).
   6. If `cl_fullPresent`: `Screen_Present(0,20,512,268)` and clear the flag. If
      `cl_fadePending`, also call `Fx_FadeIn_Stub` and clear that flag.
   7. `Dirty_Flush()`. Busy-wait until timer 7 expires.
4. Loop until `cl_onLadder ≠ 0`.
5. Erase the player, flush, and remove all 4 hotspots.

**`WalkUpdate` (1168:05b5)**

This is a trimmed copy of the main room update `10e0:0447`: no doors, slots or elves, and no
`g_netX`.

*Input decode* **[O]**:
1. If `cl_input==0`:
   - If `cl_walkMouseFollow` is set and the mouse button is down, `cl_input = 0x600`.
   - Otherwise `cl_input = Hotspot_UnderHeldMouse()`.
2. If `cl_input` was already non-zero, clear `cl_walkMouseFollow`.
3. Start with L/R/U/D = the key-held flags `DAT_06f2`/`06f4`/`06ee`/`06f0` **[I: roles from
   usage]**. Mouse position is `DAT_06f6`/`06f8`.
4. Then, using `cl_input & 0xfff`:
   - 0x601: set L. Set U if mouseY < plY, or D if mouseY > plY+plH.
   - 0x602: set R, with the same U/D rule.
   - 0x600: set L if mouseX < plX, or R if mouseX > plX+plW. Same U/D rule. Set
     `cl_walkMouseFollow = 1`.

   The 0x601 / 0x602 cases are dead in practice: those hotspots have zero width and the hit test
   is half-open, so they never fire.

*Action priority* (first match wins) **[O]**:
1. `g_netAnim ≠ 0`: net animation tick.
   - frame = `netFrames[step]`.
   - Facing right: x += `dxRight[frame]`. Facing left: x −= `dxLeft[frame]`.
   - y = `yForFrame[frame]`.
   - Step 3 → sfx 0x1e. Step 6 → sfx 6.
   - step++. After 11, set to 0.
2. `g_noNetAnim ≠ 0`: same pattern with `noNetFrames`, no sound. Wraps after 11.
3. `g_coinAnim ≠ 0`: coin animation tick.
   - frame = `coinFrames[step]`, aux = `coinAuxFrames[step]`.
   - Move the player as above.
   - If aux ≠ 0: auxX = plX + `dxRight[aux]` (or plX − `dxLeft[aux]` when facing left),
     auxY = `yForFrame[aux]`, auxW/H = BNDL 300 size of aux.
   - Step 4 → sfx 0x22. Step 7 → sfx 0. Step 8 → sfx 6.
   - step++. After 13, set to 0.
4. Space (0x20):
   - If `g_nets==0`: `g_noNetAnim=1` and `QueueHint(g_coins ? 5 : 7)`.
   - Else `g_netAnim=1`.
   - Then `Nets_Add(−1)` in both cases (ignored at 0).
5. Enter (0x0d):
   - If `g_coins==0`: `QueueHint(g_nets ? 6 : 7)`.
   - Else `g_coinAnim=1`.
   - Then `Coins_Add(−1)`.

   On this screen the coin and the net are simply wasted.
6. L (wins over R): face left.
   - If U is set and not already jumping: start a jump (`g_plJumping=1`, frame=12).
   - Otherwise frame = `nextFrame[frame]`. If that is 0xff: frame=1, `g_plJumping=0`.
   - x −= `dxLeft[frame]`, y = `yForFrame[frame]`.
7. R: same as L, facing right, but x **+=** `dxLeft[frame]`. **Quirk [O]:** the right-walk branch
   reads the *left* table `0d33` (`1168:09e3 MOV AX,[BX+0xd33]; ADD [0x5ccc],AX`), whereas
   `Player_Update` (`10e0:0447`) and the net/coin animations here use `0c89` for facing right.
   The totals per cycle are the same (see §1.3), so only the per-frame spacing differs. A faithful
   port uses `dxLeft` for walking right on the climb's screen 0.
   **Confirmed in the original (M8; decision: keep), per REFERENCE_CAPTURES §R3:** walking right
   from x 80 steps +30, +8, +15, +6, +23, +12, +17, −1, so both walks are exact mirrors in x; the
   coin toss and the net swing on this screen use `dxRight` and waste a coin / a net.
8. U only: `cl_onLadder = FindLadderAtPlayer()`.
9. D only: nothing.
10. No input: frame=0, y=142.

*Finally* **[O]**:
- `g_plW/H` = BNDL 300 size of the frame.
- Clamp x: if x < 16, x = 15. If x+w > 496, x = 497−w.

### 2.7 Climbing mode

**`ClimbLoop` (1168:0a6d)** **[O]**
1. Register hotspots 0x600 (0,20,512,267), 0x601 (0,20,0,267) and 0x602 (512,20,0,267).
2. Initial state:
   - frame 0, x = `colX[cl_column] − 30`, y = 120, facing 0, size of climber frame 0.
     This pose is never drawn: the first tick climbs before drawing, so the climber appears
     already moved (frame 0 at (226,108) for column 2) [O, per REFERENCE_CAPTURES §R3].
   - Clear the creature, jump/fall/land state, `cl_climbPhase`, `cl_nextScreen` and `cl_screen`.
     (Climbing always starts on screen 0.)
3. Each tick:
   1. Timer and input exactly as in WalkLoop.
   2. `Clip_SetPlayfield(0)`, `Dirty_Clear`.
   3. `EraseCreature()`, then erase the player.
   4. `UpdateCreature()`, then `ClimbUpdate()`.
   5. `DrawCreature()`, then `DrawClimber()`.
   6. If `cl_fullPresent`: `Screen_Present(0,20,512,267)`.
   7. Flush. Wait for the timer.
4. The inner loop runs while `cl_onLadder` is set and `cl_nextScreen == cl_screen`.
5. On leaving the inner loop:
   - If `cl_onLadder==0`: erase the player and flush.
   - If `cl_nextScreen ≠ cl_screen`:
     - If `cl_nextScreen < 4`: `cl_screen = cl_nextScreen`, `g_plY = cl_nextY`,
       `cl_fullPresent = 1`, `DrawScreenBackground()`.
     - Otherwise `cl_done = 1`.
6. The outer loop repeats while `cl_onLadder` is set and not done.
7. Remove hotspots 0x600, 0x601 and 0x602.

**`ClimbUpdate` (1168:0c04)**

Input decode is the same as `WalkUpdate`, but uses latch `2aa8`, and for hotspot 0x600 U is also
set when mouseY < 0x14.

States are checked in this order **[O]**:

1. **Jumping** (`cl_jumpStep` 1..4):
   - Facing right: i = step, frame = `jumpFrames[i]` (6, 7, 8, 9), x += `rightDx[i]`.
   - Facing left: i = 4−step, frame = `jumpFrames[i]` (8, 7, 6, 5), x −= `leftDx[i]`.
   - y += `jumpDy[i]`. Each jump totals ±87 px in x and 0 in y.
   - step++. When step > 4: step = 0, `cl_climbPhase = −1`, facing = 0. If
     `FindLadderAtPlayer()` fails, `cl_fallStep = 1`.
2. **Falling** (`cl_fallStep` 1..7):
   - frame = `fallFrames[s]` (10..16), x += `fallDx[s]`, y += `fallDy[s] + 32`.
   - When s == 1: sfx 0x21. This replays every 7 ticks while the fall continues.
   - If `FindLadderAtPlayer()` succeeds: fall = 0, `cl_climbPhase = −1` (grab the ladder).
   - Otherwise, if screen 0 and y > 0x6d: fall = 0, `cl_landStep = 1`.
   - Otherwise s++, wrapping 7 → 1.
3. **Landing** (`cl_landStep` 1..6):
   - frame = `landFrames[s]` (18..23), x += `landDx[s]`, y = `landY[s]`.
   - When s == 1: sfx 0x28.
   - s++. After 6: land = 0 and `cl_onLadder = 0` (back to walking).
4. **On ladder**:
   1. If `cl_climbPhase < 0`, re-attach: phase = 0, frame 0, x = `colX[cl_column]−30`, facing 0.
   2. Then, with p = phase:
      - **U**: frame = `climbFrames[p]`, x = `colX[col] + climbDx[p] − 30`, y −= `upDy[p]`.
        If there is no ladder now, set fall = 1. p==1 → sfx 0x1b; p==3 → sfx 0x19.
        p = (p+1) mod 4.
      - else **D**: same, but y += `downDy[p]` and p = (p−1) mod 4.
      - else **L**: jump = 1, facing = 1.
      - else **R**: jump = 1, facing = 0.
      - else: idle (state unchanged).
   3. Creature hit test. All of these must hold:
      - `cl_creatFrame == 3` (fully extended),
      - creature screen == screen,
      - `g_plY < creatY+52 < g_plY+110`.

      Then:
      - If `cl_column−1 == creatCol` and the creature faces right: jump = 1, facing = 0.
      - Else if `cl_column+1 == creatCol` and it faces left: jump = 1, facing = 1.

      Either push also calls `Coins_Add(−1)`.
   4. If screen 0 and y > 120: `cl_onLadder = 0` (stepped off the bottom).
5. **Always, at the end**:
   - `g_plW/H` = climber frame size.
   - If y < −35: `cl_nextScreen = screen+1`, `cl_nextY = y+267`.
   - Else if y > 231: `cl_nextScreen = screen−1`, `cl_nextY = y−267`.

**`DrawClimber` (1168:10a7)**: `Sprite_Draw(x, y, cl_climbBndl[frame], flip=0)`. Climber frames
are never mirrored; left jumps play the jump frames backwards. **[O]**

### 2.8 Wall creature (Master of Mischief)

**`UpdateCreature` (1168:1143)** **[O]**
1. If inactive (`tick==0`):
   - Never spawns on screen 0.
   - Spawns when `R(1000) < spawnPermille[g_rankTier]` (0/5/10/20 % per tick).
   - On spawn: tick = 1.
   - Pick a random column c = `R(5)`, retrying while `cell(screen,c)==1`. (The creature appears
     only where there is no full ladder.)
   - y = `R(range − creatH[0]) + 20`, where range = 267 if `cell==0` and 121 if `cell==2`
     (above the half ladder).
   - flip: 0 for column 0, 1 for column 4, otherwise `R(2)`.
   - Record the creature screen = screen.
2. If active but the creature screen ≠ screen: tick = 0, and stop here.
3. If tick > 12: tick = 0, and stop here.
4. frame = `creatSeq[tick]`. If frame ≥ 0:
   - x = `colX[c] − 41`. If flip, add `creatW[0] − creatW[frame]` (keeps the right edge
     anchored).
   - tick 2 → sfx 0x1d. Tick 3 → sfx 5.
5. tick++.

The full cycle is 12 ticks (1.2 s): emerge 0..3, hold, retreat, hide.
Confirmed (per REFERENCE_CAPTURES §R3, tier 3): frames 0,1,2,3,3,3,3,3,2,1,0, then hidden; on
layout-0 screen 1 only column 0 qualifies (x = colX[0] − 41 = 41); the push costs a coin in the tick
the creature reaches frame 3, and a creature outside the y window does not push.

**`EraseCreature` (1168:10d2)**: if tick ≠ 0: `Surf_Restore(x, y, creatW[frame], creatH[frame],
0x180)`. **[O]**

Quirk: on the tick after the frame becomes −1, this reads `creatW[−1]` (the selector word of
`cl_creatBndl` at `6204`) and `creatH[−1]` (= `creatW[3]` = 150). The clipped result restores a
wide strip of background. This is harmless, but a port should skip the erase when frame is −1, or
erase the last drawn rect.

**`DrawCreature` (1168:1101)**: if tick ≠ 0, frame ≥ 0 and the creature screen == screen:
`Sprite_Draw(x, y, creat[frame], flip)`. **[O]**

### 4.2 Lifecycle

- **`Elf_InitSystem` (1178:01ac)**, called once by `1118:0000`: null the 7 set BNDLs, set all
  32 slots to set −1, count = 0.
- **`Elf_SpawnForLevel(count)` (1178:0251)**, called on a new game and on every level change with
  `count = 128e[g_rankTier]` **[O]**:
  1. If count == 0, return. If elves already exist, call `UnloadAll()` first.
  2. If the room is 0x31, return (no elves in the climb).
  3. Load sets 0..6 and the projectile BNDL.
  4. For each elf i: `hasItem = (i < 3 && g_quizSlots[level*3+i].q != −1)`, where `g_quizSlots`
     is at DGROUP `5f3a` (9 × 8-byte `QuizSlot {i16 q; u8 perm[3]; u8 tried[3]}`, owned by
     `1150`). So elves 0..2 of a level carry that level's three questions; `Room_Run` later asks
     slot `level*3 + (caughtElf−1)`. Then `ResetBehaviour(i)` and `PlaceRandomly(i)`.
  5. Set `elf_confined = elf_netBusy = elf_throwState = 0`.
- **`Elf_ResetBehaviour(i)` (1178:01e3)**: set = (i<3 ? (hasItem ? 3 : 0) : i<6 ? 2 : 1).
  behaviour = `set.+4`, step = 1.
- **`Elf_PlaceRandomly(i)` (1178:00d7)**:
  - x = 30 + R(250), y = 175, facing = R(2), not in the net.
  - room: start at `2ac8[level]`, then take 15 random steps. Each step goes to the right exit
    with probability 1/3 (`R(3) == 0`), otherwise the left exit. Exits are not checked for 0xff;
    this is safe because the start rooms lie on each level's ring of rooms, where every room has
    both exits (static table: 9→0x0a→…→0x10→9, 0x17→…→0x1d→0x17, 0x24→…→0x2a→0x24) **[O]**.
- **`Elf_UnloadAll` (1178:0364)**: free sets 0..6, mark the active slots free, count = 0, free
  the projectile BNDL.

### 4.3 Per-tick dispatch (called from `10e0:007d`)

- `Elf_EraseAll` (1178:0453): for each elf, call `CaughtInNet(0,i)` if in the net, else
  `handler(0,i)`.
- `Elf_UpdateAll` (1178:048d): for each elf:
  1. `CheckNetCatch(i)`.
  2. If in the net: `CaughtInNet(1,i)`. Otherwise (re-tested): `handler(1,i)`.
  3. If `g_gateWalkStarted` (`DAT_0b98`, set by `10e0:0447` for one tick when the kid starts
     the auto-walk to the locked gate) and the elf is in the player's room: set = 4,
     behaviour = `DAT_62f4` (= set 4's behaviour field = 4), step = 1, so it flees.

  After the loop, if `g_gateWalkStarted`, set `elf_confined = 1`. From then on elves turn round at
  the room edges instead of changing room (§4.5), until the next `Elf_SpawnForLevel` resets the
  flag at the level change that the gate triggers. (Behaviour 4's −2 step still moves a fleeing
  elf to the next room, because that path does not test `elf_confined`.)
- `Elf_DrawAll(yoff)` (1178:051f): `elf_drawYOff = yoff`. Then for each elf, call
  `CaughtInNet(2,i)` or `handler(2,i)`.

### 4.4 `Elf_RunScript(mode, i, frames, dx, y, sounds)` (1178:0766, far, called only from 1178) **[O]**

**Mode 0 (erase)**, only if the elf is in the player's room: `Surf_Restore(x, y, 80, 72, 0x180)`.

**Mode 1 (update)**:
1. s = step, then step++.
2. If `frames[s] == −1` (end of loop):
   - Set 1 (thrower):
     - If it is in the player's room and either (facing left and x > 319) or (facing right and
       x < 193): if `elf_throwState==0` and `R(10) < 8`, set the set to 5,
       behaviour = `DAT_6326` (= 5), and `elf_throwState = 1`.
     - Otherwise, with probability 1/30, flip facing.
   - Other sets: with probability 1/20, `ResetBehaviour(i)`. Then with probability 1/30, flip
     facing.
   - Then s = 0 and step = 1.
3. Else if `frames[s] == −2` (leave the room):
   - New room = right exit if (facing right or the left exit is 0xff) and the right exit
     ≠ 0xff; otherwise the left exit.
   - `ResetBehaviour(i)`, s = 0. x is kept.
4. Movement: x += (facing ? −1 : +1) × `dx[s]`; y = `y[s]`.
5. Call `Elf_HandleRoomEdges(i)`.

**Mode 2 (draw)**, only if in the player's room:
1. f = `frames[step−1]`.
2. flip = facing, except behaviour 4 with f ∈ {5, 6}, which is never mirrored.
3. `Sprite_Draw(x, y + elf_drawYOff, set[set].frame[f], flip)`.
4. If `sounds` is given and `sounds[step−1] ≥ 0`, play that sfx.

Sounds therefore play only for elves on screen.

### 4.5 `Elf_HandleRoomEdges(i)` (1178:0565, far, called only from 1178:09a3) **[O]**

Let r0 be the elf's room on entry.

1. **Right edge**: if x+21 ≥ 512:
   - If the right exit is 0xff or the elves are confined: facing = left.
   - Otherwise room = right exit and x −= 512 ("moved").
2. **Left edge**: else if x < −21: the same, mirrored (facing = right, or room = left exit and
   x += 512).
3. **Side path**: applies if the elf moved, r0 is not the player's room, r0 has a door exit d,
   `room[d].level == room[r0].level`, and `room[d].zone ≠ 0`. Then, with probability 1/3:
   - room = d.
   - If `room[d].leftExit == r0`: x = −40, facing right.
   - Otherwise x = 472, facing left.
4. **Room 0x24 obstacle**: if r0 == 0x24 and 0xb0 < x+42 and x < 0x146:
   - Facing right: x = 124, turn to face left.
   - Facing left: x = 336, turn to face right.

### 4.7 Thrower state machine: `Elf_Beh5_Throw(mode, i)` (1178:0cb0)

Timeline at 10 ticks/s **[O, appearance I]**: states 1–4 wind up (set-5 frames 0, 0, 1, 1); states
5–8 throw (frames 2, 3, 2, 3) while the sparkle grows (projectile frames 0..3, sfx 0x1f); state 9
flies the sparkle 20 px per tick toward the kid for up to 15 ticks (300 px). On a hit the kid loses
a coin (sfx 8) and in state 10 the coin (projectile frames 4..7) flies back to the elf over the
same number of ticks. In states 11–12 the elf holds the coin (frame 4, projectile frame 8). State
13 returns the elf to its walking behaviour. There is only one `elf_throwState`, so only one elf
throws at a time.

Ghidra's function range ends at `1178:0e24` (size 373), but the switch bodies for states 9–13
(`1178:0e25-101e`) and the jump table (`1178:101f-103f`) lie after it. The decompiled
`1178_0cb0.c` still follows them; they are not part of any other function.

**Mode 1 (update)**: if the elf is not in the player's room, force state 13. Then, by
`elf_throwState` (the step value is the elf's step field):

| State | Action | Next |
|---|---|---|
| 0 | nothing | 0 |
| 1, 2 | step 0; elf y = 195 | +1 |
| 3, 4 | step 1 | +1 |
| 5 | step 2; projFrame 0; projX = x+30 (right) or x−6 (left); sfx 0x1f | 6 |
| 6 | step 3; projFrame 1; if facing left, projX −= 7 | 7 |
| 7 | step 2; projFrame 2 | 8 |
| 8 | step 3; projFrame 3; if facing left, projX −= 41; projSteps = 0 | 9 |
| 9 | Flying (see below) | 9, 10 or 13 |
| 10 | Return flight (see below) | 10 or 11 |
| 11, 12 | step 4; projFrame 8; projX = x (left) or x+22 (right) | +1 |
| 13 | `ResetBehaviour(i)`; step = 1; state = 0 | 0 |

State 9 (flying):
1. step = 2 + (projSteps & 1). projX += 20 in the facing direction. projSteps++.
2. If projSteps > 15: miss → state 13.
3. Else, if the player is not jumping, `g_coins > 0`, and `[projX, projX+58)` overlaps
   `[plX, plX+plW)`: hit → `Coins_Add(−1)`, sfx 8, state 10.

State 10 (coin flies back to the elf):
1. step = 2 + (projSteps & 1). projFrame = 4 + (projSteps & 3). projX −= 20 in the facing
   direction. projSteps−−.
2. When projSteps ≤ 0: state 11.

**Mode 0 (erase)**, if in the player's room:
- `Surf_Restore(x−10, y−18, 50, 75, 0x180)`.
- If state ≥ 5: also `Surf_Restore(projX, 2c7d[projFrame], 58, 36, 0x180)`.

**Mode 2 (draw)**, if in the player's room:
- Elf: `Sprite_Draw(x + 2c5f[step]` (facing right) or `x − 2c69[step]` (facing left)`,
  2c73[step], set5.frame[step], facing)`.
- If 6 ≤ state ≤ 13: `Sprite_Draw(projX, 2c7d[projFrame], projBndl[projFrame], facing)`.
- Neither draw adds `elf_drawYOff`: the thrower and its projectile are always drawn at screen-layer
  y. This would only matter if a room were composed into the bg layer (`yoff = 0x180`) with a
  throwing elf in it. A throwing elf never changes room and the bg-layer compose happens on room
  entry, when the thrower (if any) is in the room just left and so is not drawn **[I]**.

## 7. Segment 1190: castle treasure hall

Each completed game adds one treasure (`g_climbsDone = DAT_65ce`). There are 43 distinct treasures,
indexed 0..42 (the index wraps mod 43). Each treasure *t* has a frame BNDL `330+t` and a looping
`DAM` animation script OTHR `20000+t`.

**Verified against the original (E9, per REFERENCE_CAPTURES §R4):** room count, pedestal indices and
positions, the animation window and the last room (background 1038, a wall at x = 437 − w) as

### 7.2 Functions

**`TreasureHall_BuildRooms` (1190:0000)** rewrites the exits and backgrounds of rooms 0..8 each
time a game starts **[O]**:
1. Let n = `g_climbsDone`. rooms = n<2 ? 2 : min(9, (n−2)/6 + 2).
2. Room 0's right exit = 1. (It would be 0xff if rooms were 1, which cannot happen.)
3. Rooms 1..rooms−2: left = i−1, right = i+1, background 1037.
4. The last room: left = i−1, right = 0xff, background 1038.

**`TreasureHall_LoadRoom` (1190:009b)** runs only if the room's zone is 0 **[O]**:
1. Fill the pedestal indices:
   - Room 0: `idx[0] = n−1`; the others are −1. This shows the newest treasure.
   - Room r ≥ 1: `idx[i] = n − 2 − 6(r−1) − i` for i = 0..5 (newest first).
   - Each value is stored as a signed char. A value > 42 is reduced mod 43. A negative value
     means an empty pedestal.
2. For each pedestal with idx ≥ 0:
   - `65d0[i] = Res_Load(330+idx)` and `65e8[i] = Res_Load(20000+idx)`.
   - Copy every frame pointer j into `5152[2da8[i]+j]`.

**`TreasureHall_UnloadRoom` (1190:01c5)**: for each pedestal with idx ≥ 0:
- If a handle exists and `Anim_IsRunning(h, script)`, call `Anim_Stop`.
- Free both resources. Set idx = −1 and handle = −1.

**`TreasureHall_Update` (1190:02a0)**, zone 0 only, runs every tick:
- Room 0: if pedestal 0 has no handle, start it:
  `h = Anim_Start(layer 0x4d, 358, 73, frameBase 2da8[0] = 20, script 65e8[0], user0 0, user1 0,
  flags 1, onEnd NULL)` (flags 1 = loop **[I]**).
- Other rooms: let cx = plX + plW/2. For each pedestal:
  - If cx is outside `[x_i, x_i+30]`: stop its animation.
  - Otherwise, if it is not animating: start it at (x_i, y_i, base_i, script_i).

  So a treasure animates only while the kid stands in front of it.

Neither path checks `idx ≥ 0` before starting **[O]**. For an empty pedestal the script pointer
is NULL (it was nulled by `UnloadRoom` or never set). `Anim_Start` (`10b8:0119`) then stores a
NULL program counter, which leaves the channel free, but still returns its index, so the
pedestal's handle becomes ≥ 0 for a channel that is not running. Consequences: in room 0 with
`g_climbsDone == 0` nothing is drawn (correct), but the handle stays ≥ 0 because `UnloadRoom` only
resets handles of non-empty pedestals. In rooms ≥ 1 the handle is reset as soon as the kid walks
away (the stop branch calls `Anim_Stop` and sets −1). A port should simply not start an animation
for an empty pedestal and should reset all six handles on unload.

## Resolved since the first draft

These were open questions in the first version of this document; other modules' owners (or a
re-check of the bytes) have settled them.

- **`5e5a` / `5e5c`** are `g_coins` / `g_nets` (HUD owner `10e8`, save record +0x16 / +0x18).
  Catching any elf with the net really does add one coin (`1178:03bb` → `Inv_AddCoins(1)`), and the
  sparkle thrower takes one away (`1178:0cb0` state 9).
- **Arrow-key flags `06ee/06f0/06f2/06f4`** are written by the window procedure (`1010:048d..0518`).
- **Zero-width hotspots 0x601 / 0x602** can never be hit: the hotspot test is half-open
  (`code_10e0-10f0.md`). Screen-edge steering is therefore dead in both the room loop and the
  climb; only hotspot 0x600 and the keys steer.
- **Help descriptor `2cfe`** is a `PagerDesc` (§5). The 5th Help-menu slot (`12fd+0x10`) is
  `1140:0000` `MenuCmd_AboutTM`, not a null pointer (the first draft misread the unrelocated
  bytes `ff ff 00 00`).
- **`5f3a`** is `g_quizSlots`: 9 elf-question slots × 8 bytes (3 per level), word 0 = −1 if empty.
- **Sound DLL**: SSND ids 7000–7099 always come from `TM0SOUND.DLL`.
- **`GateLock_Draw(0x180)` from `10e0:0447`**: during the 3-tick step-up at the gate, the
  `yoff = 0` draw already copies the open lock into the bg layer every tick. When the step-up ends,
  the erase phase has just restored the lock rect from the bg layer, so the `0x180` call (draw into
  the bg layer, then copy the screen rect over it) leaves the open lock in the bg layer either
  way. A port can simply stamp lock frame 2 into the bg layer when the gate opens.
- **BNDL 328** (room 0x24) is the fountain with frogs, not a tree; **BNDL 326** is the Master of
  Mischief in a wall window; **BNDL 310** is the sparkle/coin projectile, not a snowball.
- **`1178:0565`, `1178:0766`, `1180:0000`** are far functions (they end in `RETF`), called
  inside their segment with `PUSH CS; CALL near`.

## Open questions

1. **`DAT_0860`** gates the fade transition in `1198:0527` (and in `1160`). It is initialised to 4
   and no writer has been found by any module. `Fx_FadeIn_Stub` / `Fx_FadeOut_Stub` are stubs
   (`return 1`), so palette fades are disabled in this build anyway. Did 3 and 4 mean
   palette-device modes in the Mac/Win original?
2. ~~**Right-walk table on the climb's screen 0.**~~ **Answered (per REFERENCE_CAPTURES §R3): confirmed
   in the original; decision: keep** (`PORTING_NOTES.md` §6.1). `1168:09e3` adds `dxLeft` (`0d33`)
   when walking right, unlike `10e0:0447`, which uses `dxRight` (`0c89`); the captured x per tick is
   80 → 110, 118, 133, 139, 162, 174, 191, 190 (§2.6).
3. **Treasure index overflow.** Hall pedestal indices are computed in signed chars
   (`1190:009b`), so `g_climbsDone ≥ 129` would give wrong pedestal indices. Probably never reached.
4. **Level cut-scene part 2** (`OTHR 20201 / 20205`) is assumed to draw the frames loaded by BNDL
   410 / 412 into `5152[]`. This needs the `DAM` script decoder (`code_10b8`/`10d8` owner) to
   confirm.
5. **Empty `switch` in `Help_ShowTopic`** on 11600 / 11605 / 11607: it suggests per-topic pictures
   (`pics[]`, `picDx/Dy`) that were removed. Harmless; no resources are referenced.
6. **Room-record bytes +0x09..+0x0b, +0x0d and +0x10** and the gate position: the lock is drawn at
   x 342 / 410 / 155 in rooms 0x0b / 0x19 / 0x26, which is not the room's door x (+0x0e: 115 / 120
   / 435). The auto-walk target for the gate (`5e3e/5e40`) is answered (ARCHITECTURE.md §7.1 C10):

7. **Creature erase with frame −1** (`1168:10d2`): the original reads `creatW[−1]` / `creatH[−1]`
   (§2.8). The resulting restore is clipped and only redraws clean background, so skipping it
   should be visually identical; not yet checked in the emulator.
8. **`ElfAnimSet.+0x02`** is always written as 1 (`1178:0085`) and never read anywhere in the
   EXE (searched the full disassembly). Unknown purpose.
