# TMTWINCD.EXE code segments 1008-1030: WinG driver, WinMain/WndProc, startup checks, cursor/mouse, event queue, memory

Scope: the six small code segments `1008`, `1010`, `1018`, `1020`, `1028` and `1030` of the Windows CD
edition (`TMTWINCD.EXE`, NE segments 2-7). Each one is one Borland C++ source module. Together they
form the Windows platform layer: process start-up and shutdown, hardware and OS checks, the main
window and its message handler, the WinG back buffer, cursors and mouse, the input/event queue that
the game logic polls, and the global-memory allocator.

Sources used:
* `re\win\ghidra_export\functions\*.c`, `disassembly.asm` and `functions.tsv`.
* Raw segment bytes from `extracted\wincd\TMTWINCD\TMTWINCD.EXE`. NE segment table: seg 2 = 1008
  at file offset `0x4a00` (len 0x6c9), seg 3 = 1010 at `0x5400` (0x5fb), seg 4 = 1018 at `0x5e00`
  (0x940), seg 5 = 1020 at `0x6c00` (0x14c), seg 6 = 1028 at `0x6e00` (0x208), seg 7 = 1030 at
  `0x7200` (0x150).
* NE relocation records for seg 3.
* A headless-Ghidra disassembly of the WndProc body `1010:01c4-05c8`. Ghidra had not disassembled
  that switch body. Scratch output is in `extracted\scratch\code_1008-1030\wndproc.asm`.
* The EXE's resource table and its RT_NAMETABLE (type 15), the DIALOG resources 1, 3, 7 and 8, and
  the resident-name (export) table.
* A complete caller list built from the NE relocation records of **every** code segment (§10.1).
  Unlike `functions.tsv`, it includes call sites in the ~14 KB of code that Ghidra did not turn into
  functions. Also a raw-byte scan of all code segments for direct `DS:[disp16]` references to the
  globals in §9, used for the "never read/written" claims. Scripts:
  `extracted\scratch\code_1008-1030\v2\xrefs.py` and `dsref.py`.
* Function names used for code outside these segments come from the other `re\names\*.tsv` files.

Conventions: `[O]` marks a fact read directly from code or bytes. `[I]` marks an inference. A
global `DAT_11b8_XXXX` is written `g_name (11b8:XXXX)`, at DGROUP file offset `0x23c00+XXXX`. All
integers are little-endian. `int` is 16-bit and `long` is 32-bit. Win16 Pascal API calls push
their arguments left to right. The game's own functions are `__cdecl far`.

**No C++ classes live in these segments [O].** They have no constructors, destructors, vtable
references or `this` pointers. Every function is plain C. The only calls into Borland RTL code are
the helpers listed in §11.

## 1. Module overview

| Seg | Proposed source module | Role | Functions |
|---|---|---|---|
| `1008` | `wing.cpp` | WinG back buffer. Loads `WING.DLL` dynamically, creates the 8-bpp top-down DIB section (512x1055), builds the identity palette, blits rectangles to the window, and fills or frames rectangles directly in the DIB bits. | 9 |
| `1010` | `main.cpp` | `WinMain`, the main window procedure (`MainWndProc`), and the pause/resume hooks for app (de)activation. | 4 (+ handler code `01c4-054f` and jump tables `0550-05c7` inside the WndProc) |
| `1018` | `init.cpp` | Previous-instance check, window class registration, window creation and viewport geometry, INI path, system checks (memory, Windows version, 386 enhanced mode, colour depth, 640x480, sound), the WinG-or-GDI decision, graphics buffer set-up, and loading the data DLLs. | 11 |
| `1020` | `cursor.cpp` | Cursor table (15 slots), cursor selection, arrow and wait cursors, the mouse-move hook, the mouse-button state, and the mouse position in game coordinates. | 8 + 1 hidden (`1020:00b1`) |

| `1030` | `memory.cpp` | `GlobalAlloc`+`GlobalLock` allocator with an out-of-memory message box, the matching free, and a recursive free of loaded `BNDL` resource trees. | 3 |

## 2. Start-up and shutdown sequence (`WinMain`, `1010:0000`)

`int PASCAL WinMain(HINSTANCE hInst [bp+0e], HINSTANCE hPrev [bp+0c], LPSTR cmd [bp+08], int nCmdShow [bp+06])` returns with `RETF 0x0a` [O].

1. **Second instance** (`hPrev != 0`) [O, 1010:000c-003c]: `w = FindPrevInstanceWindow(hInst, hPrev)`.
   If `w` is not 0: when `IsIconic(w)` call `ShowWindow(w, SW_RESTORE=9)`, then call
   `SetActiveWindow(w)`. Return 0. Only one copy of the game runs at a time.
2. **First instance** [O, 1010:003e-0063]: `RegisterMainWindowClass(hInst)`, then
   `InitInstance(hInst, 1)`, then `InitGraphicsAndData()`. If any of these returns 0, WinMain
   returns 0 at once with no clean-up. `nCmdShow` is ignored and `SW_SHOWNORMAL` (1) is passed
   instead [O, 1010:0049].
3. `SetFocus(g_hwndMain)` [O, 1010:0066].
4. **Vestigial wait loop** [O, 1010:0071-00ad]: while `g_holdMainLoop (11b8:049e) != 0 ||
   IsIconic(g_hwndMain)`, call `PeekMessage(&msg,0,0,0,PM_REMOVE)` then Translate/Dispatch.
   `g_holdMainLoop` starts at 1 in the DGROUP image, but the `WM_CREATE` handler sets it to 0
   during `CreateWindow`, and no other code writes it (raw-byte search over all segments). In
   practice the loop runs only while the window is minimised [I].
5. **Game** [O, 1010:00af-00cd]: call `Font_Init` `1068:0024` (calls `1068:0000(999,0)`, which
   loads font 999, and `1068:0073(0)`), then **`GameMain` `1118:0000`** (the game main loop; it does
   not return until the player quits), then `Font_Shutdown` `1068:006b`, `Res_FreeScratch`
   `1038:0038` (frees the 280000-byte scratch buffer), `Screen_Clear` `1070:0000` (clears the
   screen to colour 0), `Wave_Stop` `1088:0114` and `Midi_Shutdown` `1090:02af` (closes the MCI
   devices).
6. **GDI clean-up** [O, 1010:00d2-0120]:
   * WinG: `WinG_Shutdown()`, `ReleaseDC(g_hwndMain, g_hdcScreen 4296)`, `DeleteObject(g_hPalette 07d4)`.
   * GDI: `DeleteObject(g_hbmBack 429a)`, `ReleaseDC(g_hwndMain, g_hdcMem 4298)` (a memory DC passed
     to `ReleaseDC`, which is a latent bug [I]), `DeleteObject(g_hPalette)`,
     `ReleaseDC(g_hwndMain, g_hdcScreen)`.
   * `g_hdcWindow (007c)` is never released [O].
7. `FreeLibrary` on `g_hTmtLib (09f0)`, `g_hGfxLib (0872)` and the nine `g_hSoundLib[0..8]
   (09de..09ee)`. Then `timeEndPeriod(16)`. Return `msg.wParam` from the last message the wait
   loop peeked. This value is uninitialised if the loop never ran [O, 1010:018c].

### 2.1 `InitInstance` (`1018:0115`) and the window and viewport geometry [O]

1. `g_hInstance (3cda) = hInst`. Then `BuildIniPath(g_iniPath (3cde))` (§3).
2. Read the system metrics and compute the **viewport origin** (the top-left of the 512x384 game
   area in client coordinates):
   ```
   W = 2*GetSystemMetrics(SM_CXBORDER=5) + 512
   H = 2*GetSystemMetrics(SM_CYBORDER=6) + GetSystemMetrics(SM_CYCAPTION=4) + GetSystemMetrics(SM_CYMENU=15) + 384
   g_viewOriginX (086e) = ((SM_CXSCREEN - W) / 2) & ~3      // C signed division, then round down to a multiple of 4
   g_viewOriginY (0870) =  (SM_CYSCREEN - H) / 2
   ```
   (W, H) is the outer size of a captioned window with a menu and a 512x384 client. The X origin is
   aligned to 4 pixels so that WinG blits start on DWORD boundaries [I].
3. `CreateWindow("RMPDEClass" (11b8:04b1), "Treasure Mountain!" (11b8:04bc), 0x01C80000
   (WS_MAXIMIZE|WS_CAPTION|WS_SYSMENU), 0, 0, SM_CXSCREEN, SM_CYSCREEN, NULL, NULL, hInst, NULL)`.
   The window covers the whole screen and has no min/max boxes or sizing frame. It is created
   without a menu (the menu is attached later by another module, probably `1078` [I]). Return 0 if
   the window cannot be created.
4. `g_hdcWindow (007c) = GetDC(hwnd)`. This DC is kept for the life of the process and is the
   destination of the WinG blits.
5. If `CheckSystemRequirements()` returns 0, return 0. The window is not destroyed.
6. `ShowWindow(hwnd, nCmdShow)`, `UpdateWindow(hwnd)`, then `g_hwndMain (3cdc) = hwnd`. Return 1.
   `g_hwndMain` is therefore still 0 while `WM_CREATE` and the first `WM_PAINT` are handled.

Reimplementation summary: 512x384 logical game screen, centred in a black window or full screen.
`MainWndProc` subtracts the viewport origin from every mouse coordinate, and painting outside the
512x384 rectangle fills with black (`1058:1578`).

### 2.3 Previous-instance search (`1018:0000`, `1018:006b`) [O]

* `FindPrevInstanceWindow(hInst, hPrev)`:
  1. `g_lpfnEnumProc (3d60) = MakeProcInstance(FIND_PREV_WND, hInst)`.
  2. `EnumWindows(g_lpfnEnumProc, (DWORD)hPrev)`, then `FreeProcInstance`.
  3. If `g_prevInstWnd (11b0:0000)` is not 0, replace it with `GetLastActivePopup(g_prevInstWnd)`.
  4. Return it. The variable lives in the 2-byte data segment 55 (`11b0`) and is reached through
     `ES = 11b0`.
* `FIND_PREV_WND` is exported as ordinal 1, `BOOL FAR PASCAL (HWND hwnd, LPARAM lParam)`, with an
  exported-callback prologue. It accepts the first top-level window (`GetParent(hwnd) == 0`) whose
  `GetWindowWord(hwnd, GWW_HINSTANCE=-6) == LOWORD(lParam)`: it stores that window in
  `g_prevInstWnd` and returns FALSE to stop the enumeration. For any other window it returns TRUE.

## 3. INI file, command line and system checks (seg 1018)

### 3.1 INI path (`BuildIniPath`, `1018:01f5`) [O]

1. Call `GetModuleFileName(g_hInstance, buf, 0x81)`, giving length `n`.
2. Scan backwards from `buf+n` while the pointer is above `buf`. At the first `\` or `:`, write NUL
   after it, leaving `n` as the separator index. Otherwise `n--`.
3. **`lstrcpy(buf, "C:\TLCWIN\TMTWINCD\")`** (11b8:04cf). This overwrites the module directory just
   computed, so the INI directory is hard-coded.
4. If `n + 13 < 0x81`, `lstrcat(buf, "TMTWIN.INI")` (04e3). Otherwise `lstrcat(buf, "?")` (04ee).

Result: `g_iniPath` = `C:\TLCWIN\TMTWINCD\TMTWIN.INI` [O]. The CD build keeps its INI on the hard
disk because the CD is read-only [I]. The same directory holds `users.dat` (see CONTEXT.md).

### 3.2 INI keys used in these segments (section `[TMTWIN]`, 11b8:053f and repeats) [O]

| Key | Default (read) | Read by | Written | Meaning |
|---|---|---|---|---|
| `Win40VersionNum` | `"858"` | `IsWindows40` 1018:07ff | Always written back (the value just read) | Threshold, in decimal, for "running on Windows 4.0". The test is `atoi(value) <= (major<<8 \| minor)` with an unsigned compare. 858 = 0x35A, which is Windows "3.90". Windows 95 reports 3.95 (= 863), so it qualifies. Windows 3.1 reports 0x30A (= 778), so it does not. |
| `UseWinG` | `"TRUE"` | `SelectWinGMode` 1018:086d (only on Win 3.x with an 8-bpp palette display) | Written only when a command-line override is given | `lstrcmp(value,"TRUE")==0` means use WinG. |
| `CheckSound` | `"TRUE"` | `CheckSoundHardware` 1018:043a | After the dialog | `"TRUE"` shows the no-sound dialog. |
| `CheckDisplay` | `"TRUE"` | `CheckDisplayMode` 1018:04d8 | After the dialog | `"TRUE"` shows the not-optimum-display dialog. |

All reads go through `GetPrivateProfileString(section, key, default, buf[0x50], 0x50, g_iniPath)`
and all writes through `WritePrivateProfileString`.

**Command line** [O, 1018:08db-093c]: if Borland `_argc (11b8:6694) >= 2` and WinG is allowed (an
8-bpp display), the first character of `_argv[1]` (`_argv` at 11b8:6696, a far array of far
pointers; `argv[1]` is at +4) chooses the mode:
* `'3'` sets `g_useWinG = 0` (plain GDI).
* `'4'` sets `g_useWinG = 1`.

The choice is saved as `UseWinG=TRUE|FALSE`. Any other first character leaves the mode alone.

### 3.3 `SelectWinGMode(BOOL allowWinG)` (`1018:086d`) [O]

```
if (g_isWin40)          g_useWinG = allowWinG ? 1 : 0;          // INI ignored on Win95
else if (allowWinG)     g_useWinG = (INI UseWinG == "TRUE");
else                    g_useWinG = 0;
if (_argc >= 2 && allowWinG && (argv[1][0]=='3' || argv[1][0]=='4')) {
    g_useWinG = (argv[1][0] != '3');  WriteProfile UseWinG = g_useWinG ? "TRUE" : "FALSE";
}
```

### 3.4 `CheckSystemRequirements()` (`1018:0281`): returns 1 to continue, 0 to quit [O]

Locals: `noPalette = 0` (bp-0e) and `allowWinG = 1` (bp-10).

| Step | Test | On failure |
|---|---|---|
| 1 | `g_isWin40 (04a4) = IsWindows40()` | — |
| 2 | `GlobalCompact(2000000)`, then `h = GlobalAlloc(GMEM_FIXED, 1850000)`. If `h` is valid, `GlobalFree(h)`. | Dialog `NOT_ENOUGH_MEMORY_DIALOG`, return 0 |
| 3 | Windows version (`GetVersion`, bytes swapped to major<<8\|minor) `>= 0x030A` | Dialog `NOTWINDOWS31`, return 0 |
| 4 | `GetWinFlags() & WF_ENHANCED (0x20)` | Dialog `Not386Enhanced`, return 0 |
| 5 | On a screen DC: `planes = GetDeviceCaps(PLANES=14)` and `bpp = GetDeviceCaps(BITSPIXEL=12)`. On a compatible memory DC: `noPalette = !(GetDeviceCaps(RASTERCAPS=0x26) & RC_PALETTE 0x100)`. | — |
| 6 | Accept only `(planes==1 && bpp==8)` or `(planes==4 && bpp==1)`. | Dialog `TooMuchColor`, return 0 |
| 7a | **8-bpp:** if `noPalette`, dialog `TooMuchColor` and return 0. Otherwise, if the screen is not exactly 640x480 (SM_CXSCREEN/SM_CYSCREEN), call `CheckDisplayMode()`; if it returns nonzero, return 0. | |
| 7b | **16-colour:** `allowWinG = 0`. Call `CheckDisplayMode()` unconditionally; if it returns nonzero, return 0. | |
| 8 | If `CheckSoundHardware()` returns nonzero, return 0. | |
| 9 | `SelectWinGMode(allowWinG)` | |
| 10 | If `g_useWinG`, call `WinG_Load()`; if it returns 0, **return 0 silently**. There is no fallback to GDI and no message. | |
| 11 | Return 1. | |

Dialogs are shown with `1080:0000(LPCSTR name, FARPROC proc)`. That helper sets
`g_modalDialogActive (09dc) = 1`, calls `App_Deactivate()`, runs `DialogBox(g_hInstance, name,
g_hwndMain, MakeProcInstance(proc))`, then calls `App_Activate()` and clears `09dc`. The template
names resolve through the EXE's **RT_NAMETABLE** (type 15, file offset `0x2ac00`) [O]:

| Template name (case-insensitive) | DIALOG id | Dialog proc used here | Return value |
|---|---|---|---|
| `INCOMPATIBLEVIDEO` | 1 | `OKDIALOGPROC` 1080:01b9 | 0 (IDOK/IDCANCEL) |
| `NOT386ENHANCED` | 2 | `OKDIALOGPROC` | 0 |
| `NOTOPTIMUMDISPLAYMODE` | 3 | `DESIGNEDFOR640X480PROC` 1080:026c | control 0xFA ("continue") gives 1 if checkbox 0xFC is checked, else 0. Control 0xFB or IDCANCEL gives −1 ("quit"). |
| `NOTWINDOWS31` | 4 | `OKDIALOGPROC` | 0 |
| `NOT_ENOUGH_FILE_HANDLES` | 5 | (not used in these segments) | |
| `NOT_ENOUGH_MEMORY_DIALOG` | 6 | `OKDIALOGPROC` | 0 |
| `TOOBADNOSOUND` | 7 | `NOMIDIPROC` 1080:0201 | Same as id 3: 1, 0 or −1. |
| `TOOMUCHCOLOR` | 8 | `OKDIALOGPROC` | 0 |

The control ids are confirmed by the DIALOG resources [O]. Dialogs 3 and 7 each hold two static
texts (ids 0xE11 and 0x1069), an auto-checkbox **0xFC** (style `0x50030003`, BS_AUTOCHECKBOX: "do
not show this again"), a default push button **0xFA** ("&Continue", BS_DEFPUSHBUTTON) and a push
button **0xFB** ("E&xit"). Dialogs 1 and 8 have one static (0xE11) and an OK button (id 1).
`NOMIDIPROC` (1080:0201) tests the ids directly. `DESIGNEDFOR640X480PROC` (1080:026c) uses a
4-entry id table at `1080:02ea` = `{2, 0xFA, 0xFB, 0xFC}` with handlers `{02d3, 02b7, 02d3, 02b5}`:
IDCANCEL and 0xFB call `EndDialog(-1)`, 0xFA calls `EndDialog(IsDlgButtonChecked(0xFC) ? 1 : 0)`,
and a click on the checkbox itself is ignored (02b5 jumps to "return FALSE"). The two procs
therefore behave identically. The EXE exports these procs by name (resident-name table: ordinal
1 `FIND_PREV_WND`, 2 `OKDIALOGPROC`, 3 `RUNIN16COLORPROC`, 4 `NOMIDIPROC`, 5
`DESIGNEDFOR640X480PROC`). `RUNIN16COLORPROC` is not used by these segments.

`CheckSoundHardware()` (`1018:043a`) [O] returns 1 only when the user chose quit:
```
check = (INI CheckSound == "TRUE");
if (1088:0000() /*waveOutGetNumDevs()!=0, also sets 11b8:09f2*/ && 1090:0000() /*MIDI usable*/) return 0;
if (!check) return 0;
r = Dialog("TooBadNoSound", NOMIDIPROC);
if (r == -1) return 1;
WriteProfile CheckSound = r ? "FALSE" : "TRUE";   // checkbox = "don't ask again"
return 0;
```
`CheckDisplayMode()` (`1018:04d8`) does the same with key `CheckDisplay`, dialog
`NotOptimumDisplayMode` and proc `DESIGNEDFOR640X480PROC` [O]. It performs no hardware test of its
own. The caller decides when to call it.

### 3.5 `InitGraphicsAndData()` (`1018:0563`): returns 1 if OK, 0 to quit [O]

* **WinG path** (`g_useWinG != 0`): `g_hdcScreen (4296) = GetDC(g_hwndMain)`, then
  `WinG_CreateBackBuffer(512, 0x41F=1055)` (§4).
* **GDI path**:
  1. Use `GetDC(0)` to read `planes` and `bpp`, then release it.
  2. Call `SystemHeapInfo(&shi)` with `shi.dwSize = 12`, and set `g_hGdiHeap (42a0) = shi.hGDISegment`.
  3. `g_hdcScreen = GetDC(g_hwndMain)`; `g_hdcMem (4298) = CreateCompatibleDC(g_hdcScreen)`.
  4. `g_paletteDevice (086c) = GetDeviceCaps(g_hdcMem, RASTERCAPS) & RC_PALETTE` (0 or 0x100).
  5. `g_hbmBack (429a) = 1058:1493(512, 1055, planes, bpp)`, which creates a DDB and checks
     `GetFreeSpace`. Select it into `g_hdcMem`.
  6. `hBits = 1058:1525(g_hGdiHeap, g_hbmBack)`, which reads the word at +0x14 of the GDI-heap
     bitmap object: the global handle of the DDB bits. This is direct access to undocumented GDI
     structures [I].
  7. If `hBits == 0`: dialog `IncompatibleVideo`, `1090:02af()`, `DeleteObject(g_hbmBack)`,
     `ReleaseDC` both DCs, return 0.
* **Common** (`1018:067a`):
  * If `g_paletteDevice` (it starts at 1, so it stays nonzero on the WinG path): when not using
    WinG, set `g_selPixels (429e) = GlobalHandleToSel(hBits)`. Then `g_hGfxLib (0872) =
    LoadLibrary("TMT256.DLL")`.
  * Otherwise (16-colour): `g_selPlanarBits (429c) = GlobalHandleToSel(hBits)`, `g_selPixels =
    1058:153b(512L, 1055L)` (a GMEM_MOVEABLE\|ZEROINIT block of 512*1055/2 bytes, locked, returned
    as a selector), then `g_hGfxLib = LoadLibrary("TMT16.DLL")`.
  * Load `TMT.DLL` into `g_hTmtLib (09f0)` and `TM0SOUND.DLL`..`TM8SOUND.DLL` into
    `g_hSoundLib[0..8] (09de,09e0,…,09ee)`. Each failed load (handle < 32) calls
    **`PostQuitMessage(0)` and carries on**. Initialisation still returns 1. The `WM_QUIT` is later
    swallowed by `Evt_GetNextEvent`'s dispatch, so a missing DLL does not stop the game cleanly
    [I].
  * `Pal_Init` `1048:02b2()` (creates the palette), then `Screen_Clear` `1070:0000()` on the GDI
    path only (clears the buffer and the screen), `timeBeginPeriod(16)`, `g_initDone (0498) = 1` (enables `WM_PAINT`
    blits), and `Res_AllocScratch` `1038:0022()` (allocates the 280000-byte resource scratch buffer
    `g_resScratch (3d8c)` with `NewPtr`).
    Return 1.

## 4. WinG back buffer (seg 1008)

### 4.1 Loading WinG (`WinG_Load`, `1008:0000`) [O]

| `3cce` | 1006 | `WinGSetDIBColorTable(hdc, start, count, RGBQUAD far*)` | yes |

nonzero.

### 4.2 Back-buffer creation (`WinG_CreateBackBuffer(int width, int height)`, `1008:00ee`) [O]

Called once with `(512, 1055)`.

1. Fill `g_wingBmi (3892)` (a BITMAPINFOHEADER followed directly by `g_wingColorTable (38ba)`,
   256 RGBQUADs):
   * biSize = 40
   * biWidth = width
   * biHeight = height * `g_dibOrientation (0084)`. The orientation is the constant −1, so the DIB
     is **top-down**: row 0 is the top row.
   * biPlanes = 1, biBitCount = 8
   * biCompression = biSizeImage = biClrUsed = biClrImportant = 0. The PelsPerMeter fields are left
     unwritten (0).
2. First call (`g_hdcWinG (007e) == 0`):
   * `g_hdcWinG = WinGCreateDC()`
   * `hbm = WinGCreateBitmap(g_hdcWinG, &g_wingBmi, &g_wingBits)`. The bits pointer is stored at
     11b8:0080 (offset) and 11b8:0082 (selector).
   * `g_selPixels (429e) = SELECTOROF(g_wingBits)`
   * `g_hbmWinGOld (0086) = SelectObject(g_hdcWinG, hbm)`.

   Later calls (the code supports re-creation, but only one call site exists):
   * Set the width and height fields again.
   * Create a new bitmap, update `g_selPixels`, `SelectObject` the new bitmap, and
     `DeleteObject` the bitmap it replaced.
3. Store the geometry:
   * `g_bufWidth (0076) = width` and `g_bufHeight (0078) = height`.
   * `g_wingStride (3890) = ((width*8 + 31) & ~31) / 8`. This is 512 for width 512. It is computed
     but not used: the pixel routines below multiply by `g_bufWidth`.
   * `g_wingRect (3880) = {0,0,width,height}` (RECT), copied with `F_SCOPY@` into
     `g_wingRect2 (3888)`.
4. Call `WinG_BuildIdentityPalette()`.
5. Call `1048:02fd(0)`, which makes VGA colour 0 (black) the current fill colour (`11b8:4191`).
6. Call `1058:097f(0, 0, width, height)`, which fills the whole buffer with the current colour.
   The buffer starts black.

Buffer size: 512 x 1055 bytes of 8-bit palette indices. The row layout is owned by seg 1058 and
documented in `code_1058-1090.md` §2.1: rows 0-383 hold the composed frame (the only rows ever
presented), rows 384-767 hold the back page (room background, used to erase sprites), and rows
788-1054 hold a pristine copy of the 512x267 play-field. That gives 1055 = 768 + 20 + 267.

### 4.3 Identity palette (`WinG_BuildIdentityPalette`, `1008:02ec`) [O]

Called by `WinG_CreateBackBuffer` and by `1048:010a` after the game palette has been loaded into
the system palette.

1. Copy the 0x404-byte LOGPALETTE template `g_logPalTemplate (11b8:008a)` (palVersion 0x300,
   palNumEntries 256, entries zeroed) to the stack with `F_SCOPY@`.
2. `GetSystemPaletteEntries(g_hdcScreen, 0, 256, entries)`.
3. Set flags: `peFlags = 0` for entries 0-9 and 246-255 (the 20 static colours). `peFlags =
   PC_RESERVED (1)` for entries 10-245.
4. For i in 0..255, set `g_wingColorTable[i] = {rgbBlue=pe.peBlue, rgbGreen=pe.peGreen,
   rgbRed=pe.peRed}`. `rgbReserved` is not written.
5. `WinGSetDIBColorTable(g_hdcWinG, 0, 256, g_wingColorTable)`.
6. `g_hPalette (07d4) = CreatePalette(entries)`.
7. `old = SelectPalette(g_hdcWindow, g_hPalette, FALSE)`. If `old` is not 0, `DeleteObject(old)`
   (this frees the previous game palette). Then `RealizePalette(g_hdcWindow)`.

Effect: DIB index *n* equals system-palette slot *n*, so `WinGBitBlt` copies bytes without colour
translation. A modern port can drop this step: keep a 256-entry RGB palette and convert indices to
RGB at present time.

### 4.4 Present (`WinG_PresentRect`, `1008:02b6`; `WinG_BlitToWindow`, `1008:0267`) [O]

The game-side entry point is `1058:05bc(x, y, w, h)` (the "present" call). It clips the rectangle
to 0..512 x 0..384, returns early on an empty rectangle, and, when WinG is active, passes a 4-word
**GRECT `{x, y, w, h}` by value** (pushed with `F_SPUSH@`) to `WinG_PresentRect`.

`WinG_PresentRect(GRECT r)` calls `WinG_BlitToWindow(r, r.x + g_viewOriginX, r.y +
g_viewOriginY)`. That function does:
```
a  = dstX & 3                     // equals r.x & 3, because the origin is a multiple of 4
WinGBitBlt(g_hdcWindow, dstX - a, dstY, (r.w + a + 3) & ~3, r.h,
           g_hdcWinG,   r.x  - a, r.y)
```
The rectangle is widened to 4-pixel-aligned columns on both sides. Its right edge never passes 512
[I: arithmetic].

### 4.5 Filling and framing in the DIB (`1008:0418`, `1008:050b`) [O]

Both take `(const RECT far *r, int colour16)`. They are the WinG branches of `1058:07d0` (fill)
and `1058:09b8` (frame).

* The colour index comes from
  `GetNearestPaletteIndex(g_hPalette, PALETTERGB(R,G,B))`.
* R, G and B are read from **`g_egaRGB (11b8:07d8)`**: 16 records of three u16 values
  `{r,g,b}` (6 bytes each). Only the low byte of each value is used. The table is the standard
  16-colour VGA palette: 0 black (0,0,0), 1 (0,0,170), 2 (0,170,0), 3 (0,170,170), 4 (170,0,0),
  5 (170,0,170), 6 (170,85,0), 7 (192,192,192), 8 (85,85,85), 9 (85,85,255), 10 (85,255,85),
  11 (85,255,255), 12 (255,85,85), 13 (255,85,255), 14 (255,255,85), 15 (255,255,255).
* Pixel address: `g_wingBits + (long)(y) * g_bufWidth + x`, using huge-pointer arithmetic (`LXMUL`
  and `__AHSHIFT`, which appears as the `0xC0` shift-count fixups).
* `WinG_FillRect`: for `y = top .. bottom-1` and `x = left .. right-1`, set the pixel to the colour
  index.
* `WinG_FrameRect`: let `w = right-left` and `h = bottom-top`.
  1. Fill row `top` across all `w` pixels.
  2. For `i = 1 .. h-3`, set the pixels `(left, top+i)` and `(left+w-1, top+i)`.
  3. Fill row `top + max(1, h-2)` across all `w` pixels.

  **The bottom edge is drawn at `bottom-2`, not `bottom-1`**, so the frame is one pixel shorter
  than GDI `FrameRect`, and when `h == 1` the second row falls outside the rectangle. This is
  observed behaviour. A faithful port should copy it only if pixel-exact output matters.
  (The reference captures confirm it in every game dialog, `REFERENCE_CAPTURES.md` §4.1, and
  `PORTING_NOTES.md` §6.1 now says **keep**.)

### 4.6 Shutdown (`WinG_Shutdown`, `1008:0230`) [O]

If `g_hdcWinG` is set: if `g_hbmWinGOld` is set, `hbm = SelectObject(g_hdcWinG, g_hbmWinGOld)`,
and if `hbm` is not 0, `DeleteObject(hbm)`. Then `DeleteDC(g_hdcWinG)` and `WinG_Unload()`.

## 5. Main window procedure (`MainWndProc`, `1010:0196`)

`LRESULT FAR PASCAL MainWndProc(HWND hwnd [bp+0e]=DI, UINT msg [bp+0c], WPARAM wParam [bp+0a]=SI,
LPARAM lParam [bp+06])` [O]. It is not exported: Borland "smart callback" code with no DS-loading
prologue. Dispatch is a linear search of the 21-word message table at **`1010:0574`**, whose
parallel handler table is at **`1010:059e`**. Messages not in the table go to `DefWindowProc`
(`1010:0535`). Unless noted otherwise, a handler returns 0 (`1010:0545`).

Mouse lParam is in client coordinates. **Game coordinates** are `gx = LOWORD(lParam) -
g_viewOriginX` and `gy = HIWORD(lParam) - g_viewOriginY`.

## 6. Input and event system (segs 1020, 1028)

### 6.1 State written by the WndProc

| Global | Type | Meaning |
|---|---|---|
| `g_evType (3d82)` | i16 | Pending event: **0** none, **1** quit (SC_CLOSE or WM_CLOSE/QUERYENDSESSION), **2** key, **3** left button down, **4** left button up, **5** right button down, **6** right button up. Each new message overwrites it. |
| `g_evP1 (3d84)` | i16 | Key code (type 2) or game x (types 3-6) |
| `g_evP2 (3d86)` | i16 | Game y (types 3-6) |
| `g_mouseX/Y (06f6/06f8)` | i16 | Last mouse position in game coordinates (mouse messages and `Mouse_GetPos`) |
| `g_mouseButtonDown (06e3)` | i16 | 1 between WM_LBUTTONDOWN and WM_LBUTTONUP |
| `g_keyUpHeld/DownHeld/LeftHeld/RightHeld (06ee/06f0/06f2/06f4)` | i16 | Arrow keys currently held. Read by segments 10e0 and 1168 (player movement [I]). |
| `g_quitRequested (049c)` | i16 | Set by WM_CLOSE/QUERYENDSESSION and consumed by `Evt_GetNextEvent` |

**Key codes** (in `g_evP1` and the input codes) [O]: an ASCII/ANSI character from `WM_CHAR`, or
`0x100 | VK` for the navigation keys: 0x121 PgUp, 0x122 PgDn, 0x123 End, 0x124 Home, 0x125 Left,
0x126 Up, 0x127 Right, 0x128 Down, 0x12D Insert, 0x12E Delete.

### 6.2 `Evt_GetNextEvent(GameEvent far *ev)` (`1028:004f`) [O]

`GameEvent` is 6 bytes: `{i16 what; i16 p1; i16 p2}`.
```
g_evType = 0; ev->what = 0;
loop:
    if (g_quitRequested)                         goto process;
    if (PeekMessage(&msg, 0, 0, 0, PM_REMOVE))   goto process;
    if (!g_appActive)                            goto loop;      // busy-wait (Win16 PeekMessage yields)
    return ev->what;
process:
    if (!g_quitRequested) { TranslateMessage(&msg); DispatchMessage(&msg); }   // the WndProc may set g_evType
    if (g_quitRequested || (g_evType != 0 && ev->what == 0)) {                  // only the FIRST event is kept
        ev->what = g_evType; ev->p1 = g_evP1; ev->p2 = g_evP2;
        if (g_quitRequested) {
            1058:05bc(0, 0, 512, 384);     // re-present the whole screen
            ev->what = 1;                  // quit
            g_quitRequested = 0;
        }
        if (ev->what == 2 && ev->p1 == 0x13)   // Ctrl+S
            1128:0151();                       // Audio_ToggleAll: toggle sound on/off (flags 11b8:0b96/0b97)
    }
    goto loop;
```
`Audio_ToggleAll` (1128:0151, documented in `code_10f8-1148.md`) [O]: if `g_soundOn (0b96)` and
`g_voiceOn (0b97)` are both 0, it sets both to 1 and restarts the current music (`Music_Resume`
`1128:00dc`). Otherwise it clears both, stops the current sound effect (`Sfx_Stop` `1170:005b`)
and stops MIDI (`Midi_Stop` `1090:0413`). Code 0x13 can reach this test only as a `WM_CHAR` character, which is **Ctrl+S**: the
`WM_KEYDOWN` handler ignores every virtual key outside 0x21-0x2E, so `VK_PAUSE` (also 0x13) never
becomes an event. The other doc calls 0x13 "Pause", but the key that triggers it is Ctrl+S [I:
Win16 TranslateMessage generates no character for the Pause key].
The function drains **every** pending message before it returns. Only the first event is reported;
later events in the same drain are lost, although mouse position and arrow-key state still update.
It returns only when the queue is empty and the application is active. The return value is the
event type (0 if nothing happened).

### 6.3 Input codes (`Input_GetCode`, `1028:0131`; `Input_PeekCode`, `1028:01f6`; `Input_Flush`, `1028:0126`) [O]

The game logic polls a single 16-bit **input code**:

* `Input_GetCode()`:
  * If `g_pendingInputCode (06ec)` is not 0, return it and clear it.
  * Otherwise call `Evt_GetNextEvent(&ev)` and switch on `ev.what` (jump table at `1028:01e8`):

    | ev.what | Return |
    |---|---|
    | 0 | 0 |
    | 1 (quit) | `0x1B` (the same as Esc) |
    | 2 (key) | `ev.p1` (the key code) |
    | 3 (L down) | `id = HitTest(ev.p1, ev.p2)`, then `id ? (id \| 0x8000) : 0` |
    | 4 (L up) | `HitTest(...)` without a flag (0 if no hot spot) |
    | 5 (R down) | `id ? (id \| 0x4000) : 0` |
    | 6 (R up) | `id ? (id \| 0x2000) : 0` |
* `HitTest` is `Hotspot_HitTest` `1098:00b8(x, y)` (another module). It scans the 50 hot-spot records at
  `11b8:4b7a` (10 bytes each: `{u16 id, i16 x, i16 y, i16 w, i16 h}`) from index 49 down to 0 and
  returns the `id` of the first record with `id != 0` and `x <= px < x+w`, `y <= py < y+h`, or 0 if
  none matches.
* `Input_PeekCode()`: if `g_pendingInputCode == 0`, set it from `Input_GetCode()`. Return it
  without consuming it.
* `Input_Flush()` calls `Evt_FlushMessages()` and clears `g_pendingInputCode`.
  `Evt_FlushMessages()` (`1028:0013`) Peeks, Translates and Dispatches every pending message, then
  sets `g_evType = 0`. Pending input is therefore discarded, but the WndProc side effects (held
  keys, mouse position) remain.
* `Evt_PostKey(int key)` (`1028:0000`): `g_evType = 2` and `g_evP1 = key`.

### 6.4 Cursors and mouse (seg 1020) [O]

* `Cursor_LoadSet(const WORD far *ids)` (`1020:0000`):
  1. Zero the 15 slots of `g_cursors[15] (3d64)`.
  2. For `i = 0..14`, stop at the first `0xFFFF`; otherwise set `g_cursors[i] =
     LoadCursor(g_hInstance, MAKEINTRESOURCE(ids[i]))`.

  The game main (`1118:0034`) passes `11b8:1292` = `{0x80, 0x81, 0x82, 0xFFFF}`, which are the
  EXE's GROUP_CURSOR resources 128, 129 and 130.
* `Cursor_FreeSet()` (`1020:005c`): call `DestroyCursor` on each non-zero slot and zero it.
* `Cursor_Select(int idx)` (`1020:008b`): `old = g_curCursorIndex (06e9, initially −1)`, set
  `g_curCursorIndex = idx`, `SetCursor(g_cursors[idx])`, and return `old`. There is no range check.
* `Cursor_SetArrow()` (`1020:00de`): `SetCursor(LoadCursor(NULL, IDC_ARROW))`.
  `Cursor_SetWait()` (`1020:00f2`): `SetCursor(LoadCursor(NULL, IDC_WAIT=0x7F02))`.
* `Mouse_SetMoveHook(FARPROC f)` (`1020:00be`): swaps `g_mouseMoveHook (06e5, far ptr)` and
  returns the old hook. `Room_Run` installs `Player_UpdateCursor` `10e0:0000` at `10e0:0116`; that
  hook picks the cursor shape for the mouse position via `Cursor_Select` (`code_10e0-10f0.md`).
  Nothing removes the hook again.
* `Mouse_CallMoveHook()` (`1020:00b1`, 13 bytes; **not a Ghidra function**): bytes
  `66 83 3e e5 06 00 74 04 ff 1e e5 06 cb`, meaning "if `g_mouseMoveHook` is not NULL, call it".
  The relocation record at `1010:046a` confirms the call site in `WM_MOUSEMOVE`.
* `Mouse_IsButtonDown()` (`1020:0106`): returns `g_mouseButtonDown` (the Mac `Button()`
  equivalent).
* `Mouse_GetPos(int far *x, int far *y)` (`1020:010a`): `GetCursorPos`, `ScreenToClient(g_hwndMain)`,
  then `*x = g_mouseX = pt.x - g_viewOriginX` and `*y = g_mouseY = pt.y - g_viewOriginY` (the Mac
  `GetMouse()` equivalent; values may be outside 0..511 / 0..383).

## 7. Memory helpers (seg 1030) [O]

* `void far *NewPtr(DWORD size)` (`1030:0000`):
  1. `h = GlobalAlloc(GMEM_MOVEABLE, size)`.
  2. If that fails, `GlobalCompact(1000000)` and retry.
  3. If it still fails, `MessageBox(NULL, "You are out of memory." (06fc), "Memory Allocation
     Failed" (0713), MB_SYSTEMMODAL|MB_ICONHAND = 0x1010)`.
  4. Return `GlobalLock(h)`. This is NULL when `h == 0`; the caller is not stopped.
* `void DisposePtr(void far *p)` (`1030:005d`): `h = GlobalHandle(SELECTOROF(p))`, then
  `GlobalUnlock(h)` and `GlobalFree(h)`.
* `void DisposePtrDeep(void far *p)` (`1030:0082`). This is the recursive release used for
  loaded resources. It has **60 relocation call sites** (§10.1) in segments 1038, 1058, 1068, 10c0,
  10c8, 10e8, 10f0, 1100, 1110, 1138, 1150, 1160, 1168, 1170-1198, among them `Res_FreeScratch`
  `1038:0038`.
  1. If `memcmp(p, "BNDL" (11b8:072c), 4) == 0`: `n = Bndl_GetCount(p)` = `*(u16 far*)(p+4)`
     (`1038:0088`). For `i < n`, call `DisposePtrDeep(*(void far* far*)(p + 8 + 4*i))`.
  2. If `memcmp(p+6, "BNDL" (11b8:0731), 4) == 0`: `n = *(u16 far*)(p+10)`. For `i < n`, call
     `DisposePtrDeep(*(void far* far*)(p + 14 + 4*i))`.
  3. `DisposePtr(p)`.

  The on-disk BNDL (TMT.DLL type 32513) is `"BNDL", u32 count, u32 ids[count]`. The resource loader
  (`1038:076f`) expands it in a buffer of twice the size: each id slot `p+8+4i` becomes a far
  pointer to the loaded member, and a second table of member sizes follows at `p+8+4n` (see
  `code_1038-1050.md` §2.2) [O there]. Only the first `n` slots are followed here, so the size
  table is never treated as pointers. The test at offset 6 matches the seg-1038 **"flat" format**
  `{u8 'F'; u8 0; u32 size; payload}`, whose 6-byte header is followed by an expanded BNDL. Only
  dead code (`1038:08eb`, `1038:09e4`, `1038:0ad2`) builds that format. A NULL member pointer would
  fault, because there is no NULL check.

  Port note: in a modern engine this is simply "destroy the resource and, if it is a bundle, its
  members". Ownership is a tree with no sharing.

Naming note: these three routines carry the Mac Memory Manager names `NewPtr`, `DisposePtr` and
`DisposePtrDeep` in all docs and names files (ARCHITECTURE.md §7.2; earlier drafts of this doc called
them `Mem_AllocLocked`, `Mem_FreeLocked` and `Mem_FreeBundleTree`).

## 12. Reimplementation notes (what to replicate)

1. **Logical screen**: 512x384, 8-bit indexed, top-down, plus an off-screen area for a total
   buffer of 512x1055. Present = copy a sub-rectangle of rows 0..383 to the window, scaled or
   centred on a black background. The WinG and GDI paths have the same visible behaviour, so a
   port needs one path. Keep a 256-colour RGB palette and convert at present time; the identity
   palette, `PC_RESERVED` flags and DC juggling are Win16 mechanics only.
2. **Configuration**: the port does not need the hardware dialogs. It can keep an INI equivalent
   for `CheckSound` and `CheckDisplay`, or drop them. `UseWinG` and `Win40VersionNum` are
   meaningless on a modern system.
3. **Input contract seen by the game logic** (needed for segments that call 1028/1020):
   * `Input_GetCode` / `Input_PeekCode` / `Input_Flush` with the exact code encoding of §6.3: ASCII
     keys, `0x100|VK` navigation keys, `0x1B` on a window-close request, and hot-spot ids with
     flags 0x8000 (left down), 0 (left up), 0x4000 (right down) and 0x2000 (right up).
   * The polled "held arrow" flags at 06ee..06f4.
   * `Mouse_GetPos` / `Mouse_IsButtonDown`.
   * The mouse-move hook.
   * Ctrl+S (char 0x13) toggles sound inside the event fetch.
4. **Pausing**: game logic and MIDI freeze while the window is inactive, while a menu is open, or
   while a modal dialog is up. The current sound effect is stopped on deactivation.
5. **Quit**: the window-close button (and an OS shutdown request) does not close the window. It
   injects a quit event (`what=1`, which becomes input code 0x1B), and the game runs its own quit
   confirmation [I: handled in game modules].
6. Faithful quirks that a port can drop: the stale
   `WM_MOUSEMOVE` coordinates (§5), the unresolved VK 0x29-0x2C jump-table entries (§5), and
   `PostQuitMessage` without aborting when a data DLL is missing (§3.5). The frame-rect bottom-edge
   off-by-one (§4.5) must be **kept**: it is visible in every game dialog (`REFERENCE_CAPTURES.md`
   §4.1).

Resolved since the first draft (kept here for traceability):
* *Row layout of the 512x1055 buffer*: answered in `code_1058-1090.md` §2.1 (see §4.2).
* *The `"BNDL"` test at offset 6 in `DisposePtrDeep`*: it matches the seg-1038 "flat" format

  `1080:02ea` (see §3.4).
* *`1068:0024` / `1068:006b` and the 280000-byte buffer*: these are `Font_Init` / `Font_Shutdown` and
  `Res_AllocScratch` / `Res_FreeScratch` (`code_1058-1090.md`, `code_1038-1050.md`).

Still open:
1. **WM_KEYDOWN jump-table entries for VK 0x29-0x2C** (`1010:0568..056f` = `0000 0568 056A 056C`).
   No relocation record of seg 3 touches them [O], so they stay as stored. Each entry holds the
   address of the previous entry, which looks like a compiler or linker back-patch chain that was
   never resolved [I]. Pressing VK_SELECT (0x29), VK_PRINT (0x2A), VK_EXECUTE (0x2B) or
   VK_SNAPSHOT (0x2C) would jump to `1010:0000` or into the jump table itself. PrintScreen normally
   produces only `WM_KEYUP` under Windows, and the other three keys are absent from PC keyboards,
   so the bug was probably never hit [I]. A port should ignore these keys.
2. **`hCursor = LoadCursor(hInst, IDC_ARROW)`** in the window class: does Windows 3.1 return NULL
   here, giving a NULL class cursor, or does it fall back to the system arrow? This decides whether
   the class resets the cursor on every `WM_SETCURSOR`. It needs a runtime test (the emulator can
   show whether the cursor flickers to an arrow between hook updates).
3. **Win40VersionNum default 858 (= "3.90")**: why this value? Possibly to catch Windows 95 betas,
   which reported 3.9x. It only affects `SelectWinGMode`, so it does not matter for a port.
4. `g_wingRect2 (3888)` and `g_wingStride (3890)` are written but never read. The raw-byte scan of
   all code segments found no direct reference. A read through a computed pointer cannot be ruled
   out, but none is known.
5. **Missing data DLL**: `InitGraphicsAndData` posts `WM_QUIT` and continues. `Evt_GetNextEvent`
   and `Evt_FlushMessages` call `PeekMessage(PM_REMOVE)` and then dispatch the `WM_QUIT` message
   (which no window procedure handles), so the request is swallowed. The game then fails later in
   the resource loader. The exact failure was not traced, because a port will report a missing file
   at start-up instead.
