# TMTWINCD.EXE code segments 1150, 1158, 1160: elf questions (quiz), users.dat I/O, Club Sign-In

Scope: NE code segments 43 (`1150`, 5422 bytes, file offset 0x16e00), 44 (`1158`, 300 bytes,
0x18800) and 45 (`1160`, 5768 bytes, 0x18a00) of `TMTWINCD.EXE`. Each segment is one Borland C++
source module. Evidence: `re\win\ghidra_export\` (functions, disassembly), DGROUP bytes at
`TMTWINCD.EXE` + 0x23c00, the NE relocation table of DGROUP (far pointers inside DGROUP are
relocated, so they show as `ff ff 00 00` in the raw bytes), and the raw resources under
`extracted\res\`. Tags: **[O]** observed in code or bytes, **[I]** inferred.

Code that Ghidra did not disassemble was recovered with a headless Ghidra run on a copy of the
project (`extracted\scratch\code_1150\scripts\DumpRanges.java`): the switch-case bodies
`1150:1128-1196`, `1160:03b0-03ec`, `1160:05fc-0737`, and one whole function that has no entry in
`functions.tsv`, **`1160:137d` (Users_LoadSelected, 693 bytes, called from `1160:0653` and
`1160:0725`)**. Other gaps are jump/key tables: `1150:009f`, `1150:01c5`, `1150:139e` (key table),
`1160:046c`, `1160:07b8`, `1160:0dc8`. [O] A coverage check of `functions.tsv` against the
segment lengths (`extracted\scratch\code_1150_v2\gaps.py`) finds no other uncovered bytes: the
gaps are exactly `1150:009f-00a6` (switch table of 0057), `1150:01c5-01d4` (two switch tables of
00a7), `1150:132f-13c5` (tail of 100a plus the key table), `1160:042c-0487` (tail of 02e0 plus
its key table), `1160:067c-0833` (tail of 0595 plus its key table), `1160:0dc8-0dd5` (switch table
of 0cdb) and `1160:137d-1631` (Users_LoadSelected).

Names of helpers in other segments are the canonical ones from `re\names\*.tsv` (Hotspot_Set,
GameDlg_RunModal, Music_PlayZone, ...), so this document can be read side by side with the others.

## 1. Module overview

| Seg | Proposed module | Role |
|---|---|---|
| `1150` | `quiz.cpp` | The **elf question** system. When the net catches an elf, the elf asks a multiple-choice question (3 answers). The module owns the question history of the player (359 questions, 4 difficulty tiers), picks 9 questions per climb (3 elves x 3 mountain levels), draws the question screen, runs its keyboard and mouse loop, reads the question aloud (narration), grades the answer, shows the "correct, here is your clue word" or "wrong, catch me again" screen, and awards coins. |
| `1158` | `usersfile.cpp` | Raw `users.dat` read and write (`c:\tlcwin\tmtwincd\users.dat`), including creating the directories and the 4-byte file magic. |
| `1160` | `signin.cpp` | The **Club Sign-In** screen: list of up to 7 players with rank and treasure total, "Start New Player", name entry dialog, remove player (Ctrl-R), exit. Also loads a player's record into the game globals and saves the game globals back into the record (sorted table, then writes the file). |

[O] None of the three modules contains a C++ class: no constructors, destructors, vtables or
`this` pointers. All state is in DGROUP globals. No Windows API is called directly; everything
goes through helper modules (graphics 1058, text 10b0, hotspots 1098, input 1028, sound 1088,
music 1128, dialogs 10c0).

## 2. Conventions used by these modules

### 2.1 Coordinates and surfaces [O]
The game draws in a 512x384 logical space (`0x200 x 0x180`). The off-screen surface has a second
page directly below the visible one: `y + 384` (0x180) is the "back page" used to save and
restore backgrounds. `Gfx_CopyOffscreenRect(sx,sy,w,h,dx,dy)` (`1058:0b6a`) copies inside the
surface; `Gfx_BlitToWindow(x,y,w,h)` (`1058:05bc`) presents a rectangle of page 0. The play area
is `(0,20)` size `512x267` (`0x14`, `0x10b`); the status panel is `(0,288)` size `512x96`.

### 2.2 Input codes (from `Input_GetCode` `1028:0131`, see code_1008-1030.md section 6) [O]
* Keyboard: `WM_CHAR` character codes (0x08 Backspace, 0x0d Enter, 0x12 Ctrl-R, 0x1b Esc,
  printable ASCII). Navigation keys from `WM_KEYDOWN` arrive as `0x100 | VK`: 0x125 Left,
  0x126 Up, 0x127 Right, 0x128 Down.
* Mouse over a registered hotspot `id`: `id | 0x8000` left button down, `id` left button up,
  `id | 0x4000` right down, `id | 0x2000` right up. The modules here test `& 0xfff` for the id
  and treat 0x8000/0x4000 as "press" and plain/0x2000 as "release/activate".
* Window close request: 0x1b.
* Hotspots: `Hotspot_Set(id,x,y,w,h)` = `1098:0016`, `Hotspot_Remove(id)` = `1098:0089`,
  `Hotspot_ClearAll()` = `1098:0000` (50 slots at 11b8:4b7a, 10 bytes each; hit test scans slot 49
  down to 0, see `1098:00b8`).

## 3. Segment 1150: elf questions (quiz)

### 3.1 Data structures

**QuizSlot** (8 bytes, array `g_quizSlots[9]` at 11b8:5f3a) [O]

| Off | Type | Field | Meaning |
|---|---|---|---|
| +0 | int16 | `q` | Question index 0..358, or -1 (0xffff) = no question (elf already answered). |
| +2 | uint8[3] | `perm` | `perm[displayPos]` = answer index shown at that position. Answer index 0 is the correct one. |
| +5 | uint8[3] | `tried` | 1 if the answer at that display position was already chosen and was wrong. |

Slot numbering: `slot = 3*level + elf` with level 0..2 (`g_rooms[g_room]` byte +0x1a, 11b8:23f2)
and elf 0..2 [O, from `10e0:01b8-01d4`].

**Question status** `g_quizStatus[359]` (11b8:5f83) [O]:
0 = never asked (or reset), 1 = answered correctly with no wrong attempt, 2 = last attempt was
wrong, 3 = answered correctly after at least one wrong attempt. Bit 7 (0x80) = "picked for this
climb", set by Quiz_PickByStatus and cleared by Quiz_NewRound (the byte is saved to disk as is).

**Question tiers** (`g_quizTier`, 11b8:5f82, 0..4) with start table `g_quizTierStart`
(11b8:1de7) = `{0, 63, 179, 302, 359}` [O]:

| Tier | Question indices | Count |
|---|---|---|
| 0 | 0..62 | 63 |
| 1 | 63..178 | 116 |
| 2 | 179..301 | 123 |
| 3 | 302..358 | 57 |
| >=4 | 0..358 (all) | 359 |

**Per-question tables in DGROUP** [O]:
* `g_quizVoiceBase[359]` u16 at 11b8:1990: first narration SSND id of the question
  (4000, 4008, 4015, ... 6608). Sounds of question q: `base+0 .. base+nLines-1` = question
  lines, `base+nLines+a` = answer index a (0..2). SSND ids 4000..6615 live in TM2..TM8SOUND.DLL.
* `g_quizVoiceBank[359]` u8 at 11b8:1c60: narrator bank 1, 2 or 3 (124 / 129 / 106 questions).
  Bank b uses sound base `7300 + 100*(b-1)` (0x1c84, 0x1ce8, 0x1d4c) in TM1SOUND.DLL; each

### 3.3 Question selection per climb

**Quiz_SetTierRange** `1150:0000` [O]
```
if (g_quizTier < 4) { lo = TierStart[g_quizTier]; hi = TierStart[g_quizTier+1] - 1; }
else                { lo = 0; hi = 358; }
```

**Quiz_CountStatusInRange** `1150:0057` [O]: `g_quizCount[s]` = number of `q in [lo,hi]` with
`g_quizStatus[q] == s` exactly (so entries with bit 7 set are not counted).

**Quiz_PickByStatus(s, n, out)** `1150:00a7` [O]
```
cnt = g_quizCount[s];  g_quizCount[s] = max(0, g_quizCount[s] - n);
while (n > 0 && cnt > 0) {
    r = RandBelow(cnt);
    q = lo; k = 0;                       // find the (r+1)-th q >= lo with status == s
    while (k <= r) { if (g_quizStatus[q] == s) k++; q++; }
    q--;
    out[--n] = q;  g_quizStatus[q] |= 0x80;  cnt--;
}
if (n > 0) Quiz_PickByStatus(next[s], n, out);   // next = {0->1, 1->2, 2->3, 3->0}
```
Picks are written from the end of `out` backwards. [I] Recursion never terminates if the range
holds fewer than the requested number of questions; ranges are 57+ so it cannot happen.

**Quiz_FillSlots** `1150:01d5` [O]
1. `picks[0..2] = Pick(0,3)` (unseen), `picks[3..5] = Pick(2,3)` (missed),
   `picks[6..8] = Pick(3,3)` (retried), each with the fallback chain above.
2. All 9 slots: `q = -1`, `perm = {0xff,0xff,0xff}`, `tried = {0,0,0}`.
3. For `i = 8 .. 0`: `r = RandBelow(i+1)`; the (r+1)-th slot with `q == -1` gets `picks[i]`.
4. For each slot, for `k = 2 .. 0`: `r = RandBelow(k+1)`; the (r+1)-th position with
   `perm == 0xff` gets `k`. Result: a uniformly random permutation.

**Quiz_NewRound** `1150:0327` (start of every climb) [O]
```
Quiz_SetTierRange();
for all 359 q: g_quizStatus[q] &= 0x7f;
Quiz_CountStatusInRange();
if (g_quizTier < 4 && total*80 <= g_quizCount[1]*100) {   // >= 80 % right first time
    g_quizTier++; Quiz_SetTierRange(); Quiz_CountStatusInRange();
}
Quiz_FillSlots();
```
`total = count0+count1+count2+count3` (16-bit arithmetic). At most one promotion per climb.

**Quiz_CarryMissedToNextLevel(level)** `1150:0375` [O]: only for `level < 2`. For
`i = 3*level .. 3*level+2`: if `slot[i].q != -1` and `g_quizStatus[slot[i].q] == 2`, the code does
`tmp = slot[i]; slot[i+3] = tmp; slot[i] = slot[i+3];` (8-byte `F_SCOPY@` each). This is a broken
swap: the effect is that **slot i+3 (same elf on the next level) receives the missed question with
its permutation and tried flags, and slot i keeps it too**; the question previously in slot i+3
is dropped for this climb. Re-implement as observed (copy), not as a swap.

**Quiz_ResetHistory** `1150:0314` [O]: `g_quizStatus[0..358] = 0`.

### 3.4 Question resource format and parser (Quiz_ParseQuestion, `1150:0901`)

Resource: OTHR `11000 + q` in TMT.DLL (ids 11000..11358). Bytes [O]: text in the game's text
markup, `0x0d` line breaks, escape sequences `FF ... FF` (for example `FF 05 FF`, `FF 03 nn FF`,
`FF 06 'L=1' FF`; interpreted by the text renderer 10b0, not here), then the question ends with
three consecutive line breaks, followed by the three answers separated by `0x0d`, answer 0 being
correct. Zero padding follows.

Parser (operates in place on the loaded resource) [O]:
```
seen = 0; nl = 0; end = -1; blanks = 0; g_quizLineSlots = 0; blank[0..9] = 0;
g_quizText = p = text;
```

## 8. Re-implementation notes

1. Question pool: read OTHR 11000+q from TMT.DLL and the per-question tables (voice base, voice
   bank, silent list, tier starts) from DGROUP at the offsets above (TMTWINCD.EXE file offset
   `0x23c00 + addr`); do not embed them.
2. Keep the persistence format byte-exact so existing `users.dat` files load: magic, 7 records,
   field offsets of 5.1, status bytes including bit 7.
3. Reproduce the selection RNG only if save compatibility of random choices matters; the
   distribution (uniform pick among candidates, fallback chain, shuffles) is what matters for play.
4. Observed quirks worth preserving or deciding on explicitly: carry-over copies instead of
   swapping (3.3); line hotspots ignore blank lines (3.5); Esc in a question records nothing;
   loading a player can only turn sound off (5.7); a number with 8+ digits is drawn empty (5.5);
   the `users.dat` header is not validated on read. (Question 225 has no narration shift; 3.4,
   corrected per ARCHITECTURE.md §7.1 C15.)
5. Waits in these modules are busy loops (`Input_WaitCode`, `Input_GetCode` polling, `Delay_ms`,
   `Wave_IsPlaying` polling). A port should run them as states of a frame loop (or pump events
   inside the wait) but keep the same order: sound effect starts, picture and text are presented,
   the effect is allowed to finish, then narration, then the CONTINUE wait.
6. Map `c:\tlcwin\tmtwincd\users.dat` to a per-user data directory, but read an existing file at
   the original location if present (same 4-byte magic + 11081-byte body).

## Open questions

Resolved in revision 2 (kept for traceability):
* `g_unk13cd` (11b8:13cd), `g_quizReadingAll` (11b8:198e) and `g_signInBackdrop` (11b8:2259) are
  **write-only** [O]: a raw byte search of every code segment of TMTWINCD.EXE for their 16-bit
  addresses (`extracted\scratch\code_1150_v2\rawsearch.py`) finds only the stores listed in this
  document. A port can drop them.
* `DlgDesc` layout and the name-entry hotspots: see 5.2 and 5.6.
* `Text_Width` of a multi-line string is `maxX - minX` over all lines, i.e. the widest line
  (code_1098-10d8.md 7.3), so the question box is as wide as its widest line plus 6 (rounded up to
  even).
* An answered slot (`q == -1`) can never be asked: Elf_SpawnForLevel flags only elves whose slot
  has a question (section 1), only a flagged elf sets `g_caughtElf` (11b8:2ab6, at net step 7 in
  `Elf_CaughtInNet` 1178:0b1d), and on release the flag is cleared when `g_elfQuizResult`
  (11b8:0b9f, the return value of Quiz_AskQuestion) is non-zero (code_1168-1198.md, elf section).
  After a wrong answer or Esc the elf keeps its question and can be caught again.
* The SignIn side of code_10f8-1148.md open question 8: SignIn sets `g_room = 0xfe` for a new
  player (Users_InitNewPlayer, `1160:167c`) and restores the saved room (record +0x1df) for an
  existing one (Users_LoadSelected).

Still open:
1. Record bytes 0x1e0..0x4ff (800 bytes) and 0x62c are never read or written by any code found;
   possibly a Mac-edition leftover. Because the table is re-read from disk before each save and
   RemovePlayer only clears `name[0]` of the last record, these bytes (and whole stale records)
   can carry old data. Confirm with a real `users.dat` written by the game.
2. Meaning of the per-level arrays 5ea8/5eab/5eb4 and of the per-room bytes saved at record
   +0x500/+0x596 (owned by segment 1100 and the room code).
3. Why the result screens redraw the speaker icon at (438,220) before drawing picture 2011
   (`1150:04cc`, `07a0`). The keyed picture (x 33..450, y 60..264) overlaps only the left 13
   columns and upper 45 rows of the icon (x 438..481, y 220..283), so most of the icon stays
   visible on the result screen, even when voice is off (the question screen draws the icon only
   when voice is on). Whether that is intended is unknown; a port should copy it.
4. ~~Can a lower level be re-entered?~~ **Answered (ARCHITECTURE.md §7.1 C22)**: no exit leads from
   a higher level to a lower one (`dgroup_map.md` §4.16), so the copy that
   Quiz_CarryMissedToNextLevel leaves in the old slot (3.3) is never seen again in the same climb.
5. ~~Question 225 narration shift~~ **Answered (corrected per ARCHITECTURE.md §7.1 C15)**: no
   shift; lines 5613..5617, answers 5618..5620, and 5621 is an unused duplicate of 5620 (3.4).
6. Codes 0x2125..0x2128 in the quiz key table and 0x24a9..0x24af in the list key table are
   "right button released over hotspot 0x125..0x128 / 0x4a9..0x4af". No code registers hotspots
   0x125..0x128 or 0x4a9..0x4ac (byte search), so these entries look dead, unless an id is
   computed at run time somewhere. [I] They suggest that an earlier design had on-screen arrow
   and Remove/Exit buttons on the sign-in panel.
