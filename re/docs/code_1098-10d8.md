# TMTWINCD.EXE code segments 1098–10d8: hot spots, timers, text, animation scripts, dialog boxes

Scope: NE code segments 20–28 of `TMTWINCD.EXE` (Ghidra selectors `1098` … `10d8`), 9 909 bytes in all.
Evidence: `re/win/ghidra_export` (decompiled C, `disassembly.asm`, `functions.tsv`), plus a re-analysis
of a scratch copy of the Ghidra project in which I recovered 6 jump tables and created the 3
functions Ghidra had missed (`1098:0130`, `1098:0157`, `10c0:0cde`). The scratch output is in
`extracted/scratch/code_1098/out/` (`listing.asm`, `decomp.c`). NE relocation records were parsed
with `extracted/scratch/code_1098/py/ne_relocs.py` to find every far caller (including callers
inside code Ghidra never turned into functions).

A second pass re-checked every function against the disassembly and corrected or added the
following: the pager's cancel inputs (§10.6), FA loop count 0 meaning "loop forever" (§8.1),
statistics for all 63 shipped scripts (§8.1), what stays on screen when a modal animation ends (§9.2),
and a registry of hot-spot ids (§4.1). Names of functions in other modules now follow their own
names files. The scripts for this pass are in `extracted/scratch/code_1098/v2/`: `dam_stats.py`
(script statistics), `dlgdesc.py` and `dgrelocs.py` (DGROUP descriptors and their far-pointer
relocations), and `relocs.txt` (all 215 far call sites into segments 20–28).

Conventions: `[O]` = observed directly in code or bytes; `[I]` = inference. Addresses are `SSSS:OOOO`.
`DAT_11b8_XXXX` / `11b8:XXXX` is a DGROUP offset (file offset `0x23c00 + XXXX`). All integers
are little-endian. "far cdecl" means Borland `__cdecl far`: arguments pushed right to left, the
caller pops them, `[bp+6]` is the first argument (`[bp+4]` for near functions).

No C++ appears in these modules [O]: there are no constructors, destructors, vtables or `this`
pointers. Every function is a plain `__cdecl` routine that works on DGROUP globals. The only Borland
RTL helper used is `F_SCOPY@` (`1000:02f7`, far struct copy: `CX` = byte count, `src` pushed last). The
only Windows API used is `MMSYSTEM.timeGetTime` (`10a8:0007/0018/002e/004d/006a`).

|---|---|---|---|---|

| `10b8` | 24 | 2383 | `anim.c` | Animation-script interpreter: 16 channels running `DAM` byte-code scripts, building per-frame sprite, erase and update lists. |
| `10c0` | 25 | 4232 | `dialog.c` | Game-drawn message boxes: layout, drawing, save-under, buttons, modal message and Yes/No loop, multi-page help "pager". |
| `10c8` | 26 | 529 | `helppage.c` | Builds a pager from a BNDL of (text, dx, dy) triples. **Dead code**: nothing references it. |

## 2. Data structures

### 2.1 `Hotspot` (10 bytes, array of 50 at `11b8:4b7a`) [O]

| Off | Type | Field |
|---|---|---|
| +0 | u16 | `id`. 0 marks a free slot. Ids are game-chosen constants; full list in §4.1. |
| +2 | i16 | `x` (game coordinates, 0..511) |
| +4 | i16 | `y` (0..383) |
| +6 | i16 | `w` |
| +8 | i16 | `h` |

A second 50-entry array at `11b8:4d6e` is the save area used by the dead functions `1098:0130/0157`.

### 2.2 Timer table (`11b8:4f62`, `u32[8]`) [O]

`g_timerDeadline[slot]` holds an absolute `timeGetTime()` value. Slots seen in the code [O]:
0 (`1160`, 333 ms), 4 (`10f0` 50 ms, `1138` 60 000 ms), 6 (waited on by the text renderer but **never
set**, so the wait always returns at once), 7 (the main frame timer: 100 ms in `10e0`, `1138`,
`1168`; `1000/fps` in `10d8:0082`). The array ends at 0x4f82, which gives 8 slots [I].

### 2.3 `AnimChannel` (29 = 0x1d bytes, array of 16 at `11b8:4f82`) [O]

| Off | Abs (ch 0) | Type | Field |
|---|---|---|---|
| +0x00 | 4f82 | u8 | `layer`, the draw-group tag that `Anim_DrawSprites(layer, …)` selects. `Anim_Start` is called with 0x00 (10d8, 1138) and 0x4d (1190). `Anim_DrawSprites` is called with 0x00, 0x14, 0x4d and 0x57 (1198:044b/047c/048a draws 0x14, 0x57, 0x00 in that order, interleaved with other drawing). |
| +0x01 | 4f83 | u8 | `stop`. When non-zero the next `Anim_Step` executes opcode `FF` (END) instead of reading the script. |
| +0x02 | 4f84 | u8 | `flags`, copied into every sprite the channel emits (§2.4 `sflags`). Every caller passes 1 (queue erase rects), so the bit 1 path of §8.3 never runs in the shipped game [O]. |
| +0x03 | 4f85 | i16 | `x` origin, added to sprite and update-rect x |
| +0x05 | 4f87 | i16 | `y` origin. Added to sprite y. For opcode F9 only its **low byte** is added, 8-bit wrap. |
| +0x07 | 4f89 | i16 | `frameBase`, added to the script's frame byte to index `g_animFrames` |
| +0x09 | 4f8b | i16[2] | `loopCount[2]`, the counters for opcode FA. −1 = idle. |
| +0x0d | 4f8f | i16 | `user0`: written by `Anim_Start` at `10b8:01eb` and **never read** anywhere in the EXE (the only instruction that touches 0x4f8f) |
| +0x0f | 4f91 | i16 | `user1`: written at `10b8:01e7`, never read |
| +0x11 | 4f93 | far fn ptr | `onEnd`, called (no arguments, `CALLF`) when the script executes END. NULL = none. All 5 `Anim_Start` calls pass NULL (calls at `10d8:00b8`, `1138:00ee`, `1138:0246`, `1190:02e0`, `1190:0354`) [O]. |
| +0x15 | 4f97 | far ptr | `cursor`, the next script byte. **NULL = free channel.** |
| +0x19 | 4f9b | far ptr | `base`, the script start (points at the 4-byte tag). FA jump offsets are relative to it. |

### 2.4 `AnimSprite` (14 bytes, per-frame queue at `11b8:5666`, count `g_animSpriteCount` @`0b20`) [O]

| Off | Type | Field |
|---|---|---|
| +0 | u8 | `layer` (copied from the channel) |
| +1 | u8 | `noDirty`: 1 if the channel's script tag starts with `"DOP"` |
| +2 | i16 | `x` = chan.x + dx |
| +4 | i16 | `y` = chan.y + dy |
| +6 | u8 | `mode` from the script. Bit 0 = mirror / variant (see §8.3). Bit 1 = stamp into the background page. |
| +7 | far ptr | `pixmap` = `g_animFrames[frameBase + frame]` |
| +0xb | u8 | `sflags` = chan.flags. Bit 0 = queue an erase rect. Bit 1 = use the opaque / white-key draw and present immediately. |
| +0xc | i16 | frame index (frameBase + frame); stored but not used by this module |

### 2.5 `AnimEraseRect` (9 bytes, at `11b8:52e2`, count @`0b1e`) [O]

`{u8 noDirty; i16 x; i16 y; i16 w; i16 h}`, filled with `w = width+2` and `h = height+2` of the
drawn pixmap.

### 2.6 `AnimUpdateRect` (6 bytes, at `11b8:5bde`, count @`0b22`) [O]

`{i16 x; u8 y; i16 w; u8 h}`, packed with no alignment. `y` and `h` are zero-extended bytes when used.

Array capacities are not checked anywhere [O]. The spacing of the globals gives 100 frame pointers
(`5152..52e1`), 100 erase rects (`52e2..5665`), 100 sprites (`5666..5bdd`) and 16 update rects
(`5bde..5c3d`) [I].

### 2.7 Frame table `g_animFrames` (`11b8:5152`, `PixMap far*[≈100]`) [O]

Written only by `Anim_LoadBundle` (`10d8:006e`) and by the store at `1190:0196` (another module) [O]. A `PixMap` in memory starts with
`u16 width, u16 height` (see `fmt_pmap.md` and `code_1058` names).

## 4. Segment 1098: hot spots

| Addr | Name / signature | Behaviour [O] |
|---|---|---|
| 1098:0000 | `void Hotspot_ClearAll(void)` | `id = 0` for all 50 records. The rectangles stay. Called by 1160:0300/052b/07b0. |
| 1098:0016 | `void Hotspot_Set(u16 id, i16 x, i16 y, i16 w, i16 h)` | Find the first record with this `id`. If there is none, take the first record with `id == 0`. Write all 5 fields. **Quirk:** if the id is absent and the table is full, the index is 50 and the write lands on `g_hotspotsSaved[0]` (11b8:4d6e). 33 far call sites (NE relocations). |
| 1098:0089 | `void Hotspot_Remove(u16 id)` | Clear the `id` of the first record with that id. |
| 1098:00b8 | `u16 Hotspot_HitTest(i16 px, i16 py)` | For i = 49 down to 0: return `id` if `id != 0 && x <= px < x+w && y <= py < y+h` (signed compares). Otherwise return 0. **Priority:** the highest slot index wins. New spots go into the lowest free slot, so a later registration normally overrides earlier, larger ones such as the full-screen 0x44e/0x44f. Called by `Input_GetCode` (1028:0131) for mouse events. |
| 1098:0130 | `void Hotspot_SaveAll(void)` | Not a Ghidra function. No relocation or near call references it (dead) [O]. For i < 50: `F_SCOPY@(&g_hotspots[i] → &g_hotspotsSaved[i], 10)`. |
| 1098:0157 | `void Hotspot_RestoreAll(void)` | Dead. The reverse copy. |
| 1098:017e | `u16 Hotspot_PollMouseDown(void)` | If `Mouse_IsButtonDown()` (1020:0106): `Mouse_GetPos(&x,&y)` and return `Hotspot_HitTest(x,y) \| 0x8000` (0x8000 alone when no spot is hit). Otherwise return 0. Used for press-and-hold (10e0:0480, 1168:05de, 1168:0c2d) [I]. |

Input-code convention, from `Input_GetCode` (documented in `code_1008-1030.md` §6.3) [O]: a key gives
its character code, or `0x100|VK` for PgUp/PgDn/End/Home/arrows/Ins/Del. A mouse event over a hot
spot gives `id|0x8000` (left down), `id` (left up), `id|0x4000` (right down) or `id|0x2000`
(right up). Window close gives 0x1B.

## 5. Segment 10a0: wait for input

`10a0:0000 u16 Input_WaitCode(void)`: repeat `Input_GetCode()` until it is non-zero, then return
it [O]. This is a busy loop; `Evt_GetNextEvent` pumps messages. Callers: 10f0:065d, 1150:10f9,
1160:05d9.

## 6. Segment 10a8: delays and deadline timers

All comparisons are unsigned 32-bit (`JC`), so a `timeGetTime` wrap (49.7 days) is not handled [O].

| Addr | Signature | Behaviour [O] |
|---|---|---|
| 10a8:0000 | `void Delay_ms(u32 ms)` | `t = timeGetTime() + ms`, then spin while `timeGetTime() < t`. Used by `Dlg_FlashButton` (62 ms) and 1150:148b/14ab (250 and 500 ms). |
| 10a8:002a | `void Timer_Set(i16 slot, i32 ms)` | `g_timerDeadline[slot] = timeGetTime() + ms` |
| 10a8:0049 | `void Timer_Wait(i16 slot)` | spin while `timeGetTime() < g_timerDeadline[slot]` |
| 10a8:0066 | `i16 Timer_Expired(i16 slot)` | `timeGetTime() >= g_timerDeadline[slot]` |

For a port: `Delay_ms` and `Timer_Wait` should sleep or yield and keep pumping events. The original
freezes the message loop (Win16 cooperative scheduling).

| `00` | end of string |
| `09` | tab: x = the first tab stop `> x` (stops are relative to x0, default 40, 80, …, 320; unchanged if x is past them all) |
| `0A` or `0D` | new line: y += lineH. x = x0, or the centred start of the next line when centring is on. CR and LF each count as one line, so game text uses CR only. |
| `20` | space with word wrap (§7.3) |
| `FE` | x = x0 with no line feed |
| `FF 01 n FF` | insert string `subst[n-1]` (far pointer) here, with word wrap |
| `FF 02 FF` | toggle underline |
| `FF 03 c FF` | set pen colour `c-1` (`FF 03 05 FF` = colour 4, `FF 03 01 FF` = colour 0, black) |
| `FF 04 b0 b1 … FF` | set up to 8 tab stops (quirk below) |
| `FF 05 FF` | toggle centring. When turned on, the current line is re-centred at once. |
| `FF 06 FF` | no-op |
| `FF k`, other k | k is consumed and ignored. No closing FF is skipped. |
| any other byte | glyph from the font (0x86, 0x8b and others are special key glyphs in the game font [I]) |

Tab-stop quirk [O]: the loop at `10b0:02de` reads a **16-bit** word at each byte position but advances
**one byte** at a time, until the next byte is FF or 8 stops are set. A faithful port must reproduce
this, although no shipped string seems to use `FF 04` [I].

### 7.3 `Text_Render` algorithm [O]

State: `x` (DI), `y`, `rightEdge = x0 + wrapW - 1`, `spaceW = CharWidth(' ')`,
`lineH = Font_GetHeight()`, `underline = 0`, `centre = 0`, `minX = rightEdge`, `maxX = x0`,
`tabs[8] = {40, 80, …, 320}`.

For each byte `c` (main loop at `10b0:04d9`):

1. `0` → stop. Then `*outW = maxX - minX` and `*outH = (y - y0) + lineH` (each written only if the
   pointer is non-NULL).
2. `09`, `0A`, `0D`, `20`, `FE`, `FF` are dispatched through the jump table at `10b0:0524`
   (values at +0, targets at +0x0c):
   * `20` (`0418`): `w = MeasureRun(' ', cursor, subst, 0, cursor) + spaceW`. If `x + w > rightEdge`:
     skip all following `20`/`09` bytes in the source, set `x = x0` and `y += lineH` (the space is
     not drawn). Otherwise draw the space as an ordinary character (step 3).
   * `0A`/`0D` (`03cf`): `x = centre ? x0 + (wrapW - MeasureRun(0x0A, cursor, subst, 0, cursor))/2 : x0`,
     then `y += lineH`.
   * `09` (`0393`), `FE` (`0412`): as in §7.2. Neither updates `minX`/`maxX`, so a trailing tab adds
     nothing to the measured width.
   * `FF` (`014e`): `k = *cursor++`. If `k-1 <= 5`, jump through the direct table at `10b0:0518`.
     Every branch then skips bytes up to and including the next `FF`:
     * k=1 (`016d`): `sp = subst[*cursor - 1]` and `cursor++`. Render the bytes of `sp` until NUL, with the
       same space and wrap logic. The word measure for a space inside the substitution is
       `MeasureRun(' ', cursor, subst, 1, sp)`, where `sp` already points past the space. Every other
       byte, including 09/0A/0D/FE/FF, is drawn as a glyph: no control codes are interpreted inside the
       substitution. Then skip to FF.
     * k=2: `underline ^= 1`. k=3: `SetColor(*cursor - 1)`. k=4: tab stops. k=6: nothing.
     * k=5 (`0326`): skip to FF, then `centre ^= 1`. If it is now 1:
       `x = x0 + (wrapW - MeasureRun(0x0A, cursor, subst, 0, cursor))/2`.
3. Any other byte (`0498`): `minX = min(minX, x)`. Then `x += draw ? Text_DrawChar(x, y, lineH, c, underline, flush) : CharWidth(c)`
   and `maxX = max(maxX, x)`.
4. After each byte, `Timer_Wait(6)` (`04d1`). Inside a substitution it is called only when `flush != 0`.
   Slot 6 is never armed, so this is a no-op. It looks like a dormant "typewriter" delay [I].

Wrapping happens only at spaces. The first word of a line is never broken, and a word longer than
the line overflows. Division by 2 is signed and truncates toward zero (`CWD; SUB AX,DX; SAR AX,1`).

Edge cases [O]: for a string that draws no glyph, `outW = x0 - (x0 + wrapW - 1) = 1 - wrapW`
(negative), which is why `Text_Width` returns 0 for `""` without measuring. The wrap test is
`x + w > rightEdge` with `rightEdge = x0 + wrapW - 1`, so a run ending exactly at `x0 + wrapW - 1`
still fits.

### 7.4 `Text_MeasureRun(stop, p, subst, inSubst, substP)` [O]

Returns the sum of `CharWidth` for the bytes from `p` up to (not including) the first `stop`, `0`,
`0A` or `0D`, with these rules:
* `FF 01 n FF` switches to measuring `subst[n-1]` until its NUL, then resumes in the main string.
  Other `FF k … FF` escapes contribute nothing.
* With `inSubst = 1` the measure starts inside the substitution at `substP` and continues in the
  main string at `p` when that substitution ends.
* Inside a substitution, a NUL ends the substitution and only `stop`, `0A` and `0D` end the run.
* Bytes 09 and FE are not stops. They add `CharWidth(9)` / `CharWidth(0xFE)` to the measure even
  though the renderer moves x instead of drawing them.
* Divergence from the renderer: `MeasureRun` always skips to the next FF after `FF k`, even for a k
  outside 1..6, where the renderer skips only k (§7.2). No shipped string is known to use such a k [I].

### 7.5 `Text_DrawChar(x, y, lineH, ch, underline, flush)` [O]

1. If `underline && ch == '_'`, then `w = CharWidth('_')` and no glyph is drawn (an underscore under
   underline mode is a blank underlined cell, i.e. a fill-in blank [I]). Otherwise
   `w = Font_DrawChar(x, y, ch)`.
2. If `underline`: `Gfx_DrawHLine(x, y + lineH - 1, w)` in the current colour.
3. If `flush`: `Gfx_BlitToWindow(x, y, w, lineH)`.
4. Return `w`.

## 8. Segment 10b8: animation script engine

### 8.1 Script format (`DAM` scripts) [O]

Scripts are OTHR resources. All 63 script resources in `TMT.DLL` type 32515 (ids 20000–20050,
20100–20102, 20200/20201/20204/20205, 20300/20301/20302/20305/20308) begin with the 4-byte tag
`44 41 4D 1A` ("DAM\x1A"). Execution starts at `base + 4`. If the first three tag bytes are `"DOP"`,
the channel's sprites and erasures bypass dirty-rect tracking (`noDirty`). No shipped script has
that tag [O].

Opcodes (dispatched through `10b8:06d6`, index `op - 0xF9`). All multi-byte operands are
little-endian:

| Op | Operands | Semantics |
|---|---|---|
| `F9` | `i16 dx, u8 dy, i16 w, u8 h` | Queue an update rect `{x = chan.x + dx, y = (u8)(dy + (u8)chan.y), w = w + 2, h = (u8)(h + 2)}` in `g_animUpdateRects`. It is presented by `Anim_FlushUpdateRects`. |
| `FA` | `i16 off, u8 c` | Loop. `i = c >> 7`, `n = c & 0x7F`. If `loopCount[i] == -1`, set `loopCount[i] = n`. Then `--loopCount[i]`. If it reaches 0, set it to −1 and fall through; otherwise `cursor = base + off`. For n ≥ 1 the body runs n times. **n = 0 loops forever**: the counter goes −1 → 0 → −1 and never reaches 0, so the jump is always taken. Two independent counters allow nesting. FA does not end the frame: execution continues at the target in the same step. |
| `FB` | `u8 (ignored)` | `Sfx_Stop()` (1170:005b) |
| `FC` | `u8 (ignored), u8 snd` | `Sfx_Play(snd)` (1170:0000): plays SSND resource `7000 + snd` when sound is enabled (`0b96`) |
| `FD` | `i16 dx, i16 dy, u8 frame, u8 mode` | Queue a sprite `{layer, noDirty, chan.x + dx, chan.y + dy, mode, g_animFrames[chan.frameBase + frame], chan.flags, chan.frameBase + frame}`. |
| `FE` | none | End of this frame for this channel. |
| `FF` | none | END: call `onEnd()` if it is non-NULL, then set `cursor = NULL` (channel free). |
| `00..F8` | none | Ignored (1 byte consumed). |

Example (resource 20300, first frame): `FD 4B00 0E00 00 00`, `FD 8701 7300 01 00`, `FD 4D01 6000 02 00`,
`FD 0300 AB00 03 00`, `FE`. This is 4 sprites from frames 0–3. A later frame contains `FC 00 10`
(play sound 16, resource 7016) [O].

Statistics for all 63 shipped scripts (`v2/dam_stats.py`, a linear walk) [O]:
* Only FD, FE, FF, FA and FC occur (1027 FD, 589 FE, 63 FF, 52 FA, 32 FC). **F9 and FB never occur**,
  and no byte in 00..F8 appears as an opcode.
* Every FD has `mode = 0`, so mirroring and stamping (§8.3) are never requested.
* All 52 FA are `FA 04 00 00`: loop forever back to `base + 4`. These are the idle loops 20000–20050
  and 20100. They run until `Anim_Stop` (or `Anim_ResetAll`). The bytes after the FA (`FD … FE FF`)
  are reachable only through the stop flag, which runs FF directly.
* Sprites per frame: at most 6 (20305). Highest frame byte: 80 (20302). Script sizes: 41–1579 bytes.
* Endings: 62 scripts end with `… FE FF`, so the END runs alone in the step after the last frame.
  Only 20300 ends with `FD FD FD FD FF`, so its last frame is queued and drawn in the same step as
  the END (§9.2).
* Sounds played by FC: 2, 3, 9, 10, 11, 13, 14, 16, 17, 18, 20, 21, 23, 24, 25, 27, 33, 35, 40
  (SSND `7000 + n`). The byte before the sound number is always 0.

Scripts are walked in place in the loaded OTHR resource, with no bounds check. A script must end
in FF or loop with FA. A loop with no FE in its body hangs `Anim_Step`.

### 8.3 `Anim_DrawSprites(layer, yOff, bgYOff)` [O]

For every queued sprite `s` whose `layer` matches (in queue order, i.e. channel order, then script
order):
1. If `s.noDirty`, save `g_dirtyEnabled` and set it to 0. It is restored at the end of this sprite.
2. If `sflags & 2`: `PixMap_DrawOpaqueOrFlippedWhiteKey(s.x, s.y + yOff, pm, mode & 1)` (1058:0cf3).
   With mode bit 0 clear this is an opaque copy; with it set, a mirrored draw with white as the
   transparent key. Then, if `yOff == 0`, `Gfx_BlitToWindow(s.x, s.y, w, h)` presents it at once.
   Otherwise: `PixMap_DrawSprite(s.x, s.y + yOff, pm, mode & 1)` (1058:1320). This is a keyed
   (transparent) draw, mirrored horizontally when mode bit 0 is set, and adds a dirty rect.
3. If `mode & 2` ("stamp"): `Gfx_CopyOffscreenRect(s.x, s.y, w, h, s.x, s.y + bgYOff)` copies the
   freshly drawn area into the background page, so the sprite becomes permanent scenery. No erase
   rect is queued.
   Else, if `sflags & 1`: queue the erase rect `{noDirty, s.x, s.y, w+2, h+2}`.

`yOff` is the vertical offset of the target page. Callers pass 0 (draw on the visible page) or a
variable: `1198:0447/0478/0486` pass the `yoff` argument of `Room_DrawForeground`, and `1190:044f`
passes DI. With `yOff = 0x180` the sprite is composed into the background page. The erase rect and
the stamp source still use the unshifted `s.y` [O]. With shipped data only the
`PixMap_DrawSprite` branch and the erase-rect branch run (flags = 1, mode = 0; §2.3, §8.1).

### 8.4 Frame pipeline (as used by `Anim_PlayModal` and the room loop `10e0`) [O]

```
every frame (timer slot 7):
    Anim_EraseSprites(0x180)            // restore last frame's sprite rects from the background page
    Anim_Step()                          // advance every script by one frame
    Anim_DrawSprites(layer, 0, 0x180)    // per layer; callers interleave layers with other drawing
    Anim_FlushUpdateRects()              // explicit F9 rects
    Gfx_FlushDirtyRects()                // 1058:0731: present the dirty rects
```
`g_dirtyEnabled` must be 1 during this sequence, otherwise nothing reaches the screen except
`sflags&2` sprites and F9 rects.

### 9.1 `i16 Anim_LoadBundle(i16 bndlId, i16 frameBase, void far* far* outBndl, u8 far* far* outScript)` (`10d8:0000`) [O]

1. `*outBndl = GetResource(bndlId)` (1038:08c5). The BNDL is loaded recursively, so every entry

`DAM` script id (OTHR) and the rest are PMAP ids. Examples: BNDL 323 = {20300, 2300…2365} (66 frames);
324 = {20305, …}; 325 = {20308, …}; 400–402 = {20100–20102, …}; 410/412 = {20200/20204, …} [O].

### 9.2 `i16 Anim_PlayModal(script, frameBase, user0, user1, skippable, onEsc, x, y, fps)` (`10d8:0082`) [O]

Argument words in push order (callee view): `[bp+6..8] script far`, `[bp+a] frameBase`,
`[bp+c] user0`, `[bp+e] user1`, `[bp+10] skippable`, `[bp+12..14] onEsc far`, `[bp+16] x`,
`[bp+18] y`, `[bp+1a] fps`.

```
save g_dirtyEnabled; g_dirtyEnabled = 1; result = 0
ch = Anim_Start(layer 0, x, y, frameBase, script, user0, user1, flags = 1, onEnd = NULL)
Timer_Set(7, 0); Input_Flush()
do {
    if (Timer_Expired(7)) {
        Timer_Set(7, (i32)(1000 / fps))            // 16-bit signed divide
        Anim_EraseSprites(0x180); Anim_Step(); Anim_DrawSprites(0, 0, 0x180)
        Anim_FlushUpdateRects(); Gfx_FlushDirtyRects()
    }
    k = Input_GetCode()
    if ((k == 0x0D || k == 0x20) && skippable) { Anim_Stop(ch, script); result = (k == 0x0D) ? 1 : 2 }
    else if (k == 0x1B && onEsc) onEsc()
} while (Anim_IsRunning(ch, script))
restore g_dirtyEnabled; return result     // 0 = played to the end
```
What remains on screen depends on how the script ends [O]:
* `… FE FF` (62 of 63 scripts): in the tick after the last frame, `Anim_EraseSprites` restores the
  background under the last frame, then `Anim_Step` runs only the END. So the animation is erased
  before the function returns.
* `… FD … FD FF` (20300 only): the last frame is queued, drawn and presented in the same tick as the
  END. It stays on screen, and its erase rects stay queued for the next `Anim_EraseSprites` caller.
* Skipped with Enter or Space: `Anim_Stop` sets `stop`. In the next tick the background is restored
  and the channel runs FF at once, so the animation is erased.

Timing: the first frame is drawn on the first loop pass, because slot 7 was set to "now". Later
frames follow every `1000/fps` ms (16-bit `IDIV`, truncated; fps 0 would fault). Input is polled
between frames, every pass of the busy loop.

| Site | frameBase / user0 / user1 | skippable | onEsc | (x, y) | fps |
|---|---|---|---|---|---|
| 10f0:0126, 0155, 01b9, 0209, 02db | 0 / 0 / 0 | 1 | `1140:0098` ("Exit" Yes/No, descriptor 1533) | (0, 20) | 4 |
| 1188:007c, 0158 | 0 / 0 / 0 | 1 | NULL | (0, 0) | 7 |

### 10.3 Drawing (`Dlg_Draw(d, saveUnder)`) [O]

With `k = (type == 2) ? 0 : 3`:
1. Save the pen colour. Run `Dlg_Layout(d)`. If `saveUnder`, call `Dlg_SaveUnder()`.
2. Colour 15: `FillRect(X, Y, W, H)` (white box).
3. Picture: if `d.pic`, draw it opaque (`1058:0cf3` flag 0) at `(X+6 + picDx, Y+3+k + picDy)`.
4. Colour 0: three nested frames, `FrameRect(X+5−i, Y+2+k−i, W−13+2i, H−10−k+2i)` for i = 0, 1, 2.
5. Colour 7, drop shadow: for i = 0..2, `VLine(X+W−6+i, Y+3+k, H−6−k)` and `HLine(X+6, Y+H−6+i, W−9)`.

7. Title: `cy += 3`; colour 0; `Text_Draw(titleX, cy, title)`; `cy += 20`; `HLine(cx, cy, cw)`
   (separator).
8. Body: `cy += marginT`; colour 0; `Text_DrawBox(cx + marginL, cy, W − 25, body, NULL, 0)`.
9. Footer: colour 0; `HLine(cx, footerY − 2, cw)`; `Text_Draw(footerX, footerY, F)`.
10. Types 4, 5, 6, 7 and 9: `HLine(cx, btnY[0] − 2, cw)` (button separator).
11. Buttons: types 6–9 call `Dlg_DrawButton(1, 0)`. Types 4–9 call `Dlg_DrawButton(0, 0)`, then
    `Dlg_ToggleButton(d.defaultButton)`, which highlights the default button.
12. `Gfx_BlitToWindow(X, Y, W, H)`. Restore the pen colour.

### 10.4 Buttons (`Dlg_DrawButton(i, hi)`) [O]

With `(bx, by, bw, bh)` = button i:
1. Colour `hi ? 0 : 15`: `FillRect(bx, by+1, bw, bh−2)` and `FillRect(bx+1, by, bw−2, bh)`. Together
   they fill all but the four corner pixels.
2. Colour 0, outline with notched corners:
   * `HLine(bx+1, by, bw−2)`
   * `VLine(bx+1, by, 2)` and `VLine(bx+bw−2, by, 2)`
   * `HLine(bx, by+1, 2)` and `HLine(bx+bw−2, by+1, 2)`
   * `VLine(bx, by+1, bh−2)` and `VLine(bx+bw−1, by+1, bh−2)`
   * `HLine(bx, by+bh−2, 2)` and `HLine(bx+bw−2, by+bh−2, 2)`
   * `VLine(bx+1, by+bh−2, 2)` and `VLine(bx+bw−2, by+bh−2, 2)`
   * `HLine(bx+1, by+bh−1, bw−2)`
3. Colour `hi ? 15 : 0`: `Text_Draw(labelX[i], by + 1 + half(bh − 19), label[i])`.
4. `g_btnState[i] = hi`. The button is not presented here; callers present it.

### 10.5 `GameDlg_RunModal(d)`: types 1 and 8 only [O]

Setup:
1. Save and clear `g_dirtyEnabled`.
2. Save the pen colour.
3. Save `Menu_IsEnabled()`, then `Menu_EnableAll(0)`.
4. Save `g_cursorForced`, then `SetCursorForced(1)` (arrow cursor).
5. `Music_PauseNested()`, `Input_Flush()`.
6. `sel = d.defaultButton`.
7. `Dlg_Draw(d, 1)`, `Dlg_AddHotspots(d)`.

Loop on `k = Input_GetCode()`, ignoring 0. Any type other than 1 or 8 loops forever.

**Type 1** (table at `10c0:0cc6`):

| Input | Action |
|---|---|
| `0x0D`, `0x044E`, `0x244E` (Enter, footer left-up, footer right-up) | `sel = 0`, done |
| `0x1B`, `0x044F`, `0x244F` (Esc, click anywhere else) | `sel = −1`, done |

**Type 8** (table at `10c0:0c72`). "Toggle" means `Dlg_ToggleButton`:

| Input | Action |
|---|---|
| `0x09`, `0x125–0x128` (Tab, arrows) | Toggle(sel); `sel ^= 1`; Toggle(sel) |
| `0x0D` | `Dlg_FlashButton(sel)`; done |
| `0x1B`, `0x044E`, `0x244E` | `sel = −1`; done |
| `'N'`, `'n'`, `0x044D`, `0x244D` (No released) | if `sel == 1` Toggle(1); `sel = 0`; Flash(0); done |
| `'Y'`, `'y'`, `0x044C`, `0x244C` (Yes released) | if `sel == 0` Toggle(0); `sel = 1`; Flash(1); done |
| `0x444C`, `0x844C` (button pressed on Yes) | if `sel == 0`: Toggle(0); `sel = 1`; Toggle(1) (move the highlight only) |
| `0x444D`, `0x844D` (pressed on No) | if `sel != 0`: Toggle(sel); `sel = 0`; Toggle(0) |

0x44F, the full-screen spot, is not in the type 8 table, so clicks outside the buttons are ignored.

Exit:
1. `Dlg_RestoreUnder()`, `Dlg_RemoveHotspots(d)`.
2. Restore the cursor mode, pen colour and `g_dirtyEnabled`.
3. `Music_ResumeNested()`, `Input_Flush()`.
4. Restore the menu state.
5. Return `sel`: type 8 gives 1 = Yes, 0 = No, −1 = Esc/footer; type 1 gives 0 or −1.

### 10.6 `Dlg_RunPager(p)`: multi-page help (`10c0:0cde`) [O]

Setup:
1. Save and clear `g_dirtyEnabled`; save the colour and menu state; `Menu_EnableAll(0)`; save the
   cursor mode; `SetCursorForced(1)`.
2. `Hotspot_Set(0x44E, 0, 0, 512, 384)` (outside = cancel).
3. `Music_PauseNested()`, `Input_Flush()`.
4. Build a local `DlgDesc` from `p`: title, footer, x, y, width and lines.
5. `page = 0`, `first = 1`, `saveUnder = 1`.

Per page:
* `type = (page == 0) ? (count == 1 ? 4 : 5) : (page < count−1 ? 6 : 7)`.
* `sel = default = (page == 0) ? 0 : 1`.
* `body = texts[page]`, `pic = pics[page]`, `picDx/Dy = low bytes of picDx[page]/picDy[page]`.
* On the first page only: `Dlg_Layout` and `Hotspot_Set(0x44F, X, Y, W, H)`. This makes clicks
  inside the box inert, because 0x44F sits above 0x44E.
* `Dlg_Draw(&local, saveUnder)`; `saveUnder = 0` afterwards, so the background is saved once.
* `Hotspot_Set(0x44C, btn0)`. If `page > 0`, also `Hotspot_Set(0x44D, btn1)`.

Input loop (table at `10c0:1040`, targets at +0x24):

| Input | Action |
|---|---|
| `0x09`, `0x125–0x128` | if `page > 0`: Toggle(sel); `sel ^= 1`; Toggle(sel) |
| `0x444C/0x444D/0x844C/0x844D` (press on a button) | if the pressed index `(k & 0xFFF) − 0x44C != sel`, same as Tab (only when `page > 0`) |
| `0x044C/0x044D/0x244C/0x244D` (release on a button) | if the index differs from `sel`: Toggle(sel); `sel ^= 1`. Then `Dlg_FlashButton(sel)`; done |
| `0x0D` | Flash(sel); done |
| `0x1B`, `0x044E` (Esc, left click outside the box) | `sel = −1`; done |
| `0x121` (PgUp) | if `page > 0`: if `sel > 0` Toggle(sel); `sel = 0`; Flash(0); done |
| `0x122` (PgDn) | if `page == 0`: `sel = 0`; Flash(0); done. Else, if `page < count−1`: `sel = 1`; Flash(1); done |

The table has 18 entries [O]: 0x09, 0x0D, 0x1B, 0x121, 0x122, 0x125–0x128, 0x044C, 0x044D, 0x044E,
0x244C, 0x244D, 0x444C, 0x444D, 0x844C, 0x844D. Unlike `GameDlg_RunModal`, **0x244E is absent**, so a
right click outside the box does nothing. All 0x44F codes (clicks inside the box but off the buttons)
are ignored too. On page 0 the 0x44D spot is not registered, so the press and release handlers only
ever see index 0 there.
After "done":
1. `SetCursorForced(1)`. Remove 0x44C, and 0x44D if `page > 0`.
2. Act on `sel`: −1 → `page = −1`. 0 → `page = (page == 0) ? 1 : page − 1` (button 0 is "next" or
   "done" on page 0, "back" elsewhere). 1 → `page + 1`. (The direct table at `10c0:1038` also has an
   unreachable case `sel == 2` → `page = count`.)
3. Continue while `0 <= page < count`.

Exit:
1. `Dlg_RestoreUnder()`; restore the cursor mode; remove 0x44F and 0x44E.
2. Restore the colour and `g_dirtyEnabled`; `Music_ResumeNested()`; `Input_Flush()`; restore the
   menu state.
3. Return `page >= 0`: 1 = left via "Done" past the last page, 0 = cancelled.

## 11. Segment 10c8: pager from a BNDL (dead code)

`10c8:0000 i16 Dlg_PagerFromBndl(i16 bndlId, i16 pages, const char far* title, const i16 far* textIds)`.
There are no relocations to `10c8:0000` and no entry-table export, so it is unreachable [O]. The live
equivalent is `1180:0000`, which uses descriptor `11b8:2cfe` and text resources (another module).
Behaviour [O]:
1. Set the clip rect to the full screen (`0868=0`, `086a=511`, `0864=0`, `0866=383`).
2. `b = GetResource(bndlId)`.
3. For `i < pages`:
   * `text[i] = textIds ? GetResource(textIds[i]) : Bndl_GetEntry(b, 3i)`.
   * `dx[i]` and `dy[i]` = the word at `ES:LOWORD(Bndl_GetEntry(b, 3i+1 / 3i+2))`. ES is the bundle
     selector left by 1038:0061, which is a likely latent bug.
   * `pic[i] = GetResource(bndlId + 1 + i)`, freed and set to NULL if its first byte is 0.
4. Store `title` and `pages` into `11b8:0b78`, then call `Dlg_RunPager(&0b78)`.
5. Free everything (`DisposePtrDeep`) and return the pager result.

## 14. Re-implementation notes

* **Hot spots** are a flat 50-slot table with "highest slot wins" priority. Keep the slot-allocation
  behaviour (lowest free slot, update in place on the same id) so overlapping full-screen spots
  resolve the same way.
* **Text**: implement `Text_Render` exactly, including the CR/LF double-count, wrap only at spaces,
  `FE`, the `_` underline blank, the tab-stop quirk and signed half-division for centring. Measure
  and draw must share the same code path (the original uses one routine with a `draw` flag).
* **Animation**: one global pool of 16 channels. A frame is erase (restore from background page) →
  step → draw per layer → present. The background page is a second copy of the 512×384 frame,
  0x180 rows below the visible one in the offscreen buffer [I, from the `bgYOff = 0x180` arguments].
* **Dialogs**: the geometry tables in §10.2 and the drawing recipe in §10.3/§10.4 are sufficient to
  reproduce the boxes pixel for pixel, given the same font metrics (the layout assumes 19 px per line;
  the actual line advance is `Font_GetHeight()`).
* **Modality**: every modal loop here spins on `Input_GetCode`. A port should run these as nested
  loops (or states) that keep pumping the platform event queue.
* **Script edge cases worth matching**: FA with count 0 loops forever; FA does not end a frame; the
  stop flag replaces the next opcode with FF; `Anim_Start` returns 0 both for channel 0 and for
  "no free channel"; END in a step of its own erases the last frame (§9.2).
* **Dead code**: `1098:0130/0157` and `10c8:0000` need not be ported. Dialog types 2/3/9, opcodes
  F9/FB, sprite mode bits and channel flag bit 1 are unused by shipped data (Open question 5).

## Open questions

1. **`"DOP"` script tag**: no shipped script uses it. Was it meant for scripts generated at runtime
   (the code that fills `g_animFrames` at `1190:0196` could build some), or is it a leftover from the
   Mac version? Skipping dirty tracking presumably leaves the sprite in the offscreen buffer until
   something else presents that area.
2. **Channel words `user0`/`user1`** (`+0x0d`/`+0x0f`) are written by `Anim_Start` but never read
   anywhere in the EXE. A Mac-version leftover? A port can drop them.
3. **Timer slot 6** is waited on for every character drawn by `Text_Render` but never armed. Was a
   typewriter effect disabled for the Windows port? It is harmless to omit.
4. **Footer glyphs**: string `0b24` starts with byte 0x86, and descriptor `221a` uses 0x8b. Confirm
   against the FFNT font (resource 999) which key pictures these are (probably Esc/Return icons).
5. **Unused features with shipped data**: opcodes F9 and FB, sprite `mode` bits 0 and 2, channel
   `flags` bit 1, `onEnd` callbacks, dialog types 2/3/9 and `Dlg_PagerFromBndl` are all implemented
   but never reached (§2.3, §2.8, §8.1, §11). A port should still implement them if it aims to load
   modified data. Otherwise they can be stubs. Is any of them reachable from data the EXE builds at
   run time (for example scripts assembled in memory)? None was found.
6. **Array capacities** (frames 100, erase rects 100, sprites 100, update rects 16) are inferred from
   global spacing; nothing checks them. Shipped scripts use at most 6 sprites per frame and frame byte
   80 per script. The combined load when several channels run at once (1190 starts several
   per-object scripts on layer 0x4d, indexed arrays at `2d90/2d9c/2da8`) has not been measured.
   **Settled for the port (M6, per REFERENCE_CAPTURES §R4):** the hall's pedestal windows are disjoint
   and the hall has no elves, so at most one hall animation runs at a time; the busiest captured
   scenes (three elves with the player in rooms 15/16) showed no drawing errors, and the overflow
   cases were not reached. Decision: keep the port as it is (no fixed limits, full-frame
   presentation); there is nothing to emulate.
7. **`Dlg_PagerFromBndl` dx/dy fetch** uses `ES:LOWORD(entry)` with ES = bundle selector. Since
   the function is dead this is moot, but compare with the live `1180:0000` (outside this scope) for
   the intended help-page format.
8. **`yOff` ≠ 0 draws** (`1198:0447…`, `1190:044f`) queue erase rects at the unshifted y. Confirm with
   the room-drawing code (outside this scope) that those calls happen only while composing the
   background page, when no erase is pending, so the mismatch is harmless.
