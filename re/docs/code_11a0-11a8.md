# Code segments 11a0 and 11a8 (TMTWINCD.EXE): Borland C++ exception handling, RTTI and `string`

Scope: NE segment 53 (`11a0`, file offset `0x1ea00`, 0x3c14 bytes) and segment 54 (`11a8`, file
offset `0x22a00`, 0x0c35 bytes) of `TMTWINCD.EXE`. All addresses are Ghidra `selector:offset`.
`DGROUP:xxxx` is `11b8:xxxx` (file offset `0x23c00 + xxxx`).

Evidence used: `re/win/ghidra_export/functions/*.c` and `disassembly.asm` for the 73 functions Ghidra
found, plus my own Ghidra re-disassembly of the code Ghidra had skipped (in a copied project), the
raw segment bytes, and the NE relocation tables. Scratch scripts and listings are in
`extracted/scratch/code_11a0/` (`rel.py` resolves NE fixups, `tpid.py` decodes Borland type
descriptors, `gap1.txt`/`gap2.txt` hold the extra disassembly).

Notation: **[O]** means observed in bytes or code. **[I]** means inferred. Borland RTL names are
given where I am reasonably confident of them. Names with an `xx_` prefix are descriptive names
for internal helpers whose original RTL name I don't know.

---

## 1. Summary: what these modules are and what the port needs

* **Both segments are entirely Borland C++ 4.x runtime library. They contain no game logic,
  use no game resources and make no Windows API imports.** [O]
  * `11a0` is the C++ exception-handling engine (`xx.cpp`/`xxa.asm` in the RTL). It includes a
    software emulation of Win32-style structured exceptions for Win16: `RaiseException`, frame
    dispatch, unwinding, and support for `__try/__except/__finally`. The segment also holds RTTI:
    `typeinfo`, `typeid` and `dynamic_cast` support, plus the type descriptors for `Bad_cast`,
    `Bad_typeid` and `typeinfo`.
  * `11a8` is part of Borland's `cstring.cpp`, the reference-counted `string` class (`string`,
    `TStringRef`, `TSubString`). It also holds the type descriptors of `xmsg`, `xalloc`,
    `string::outofrange`, `string::lengtherror`, `TStringRef` and `TReference`. It is linked in
    only because `xmsg` and `xalloc` (the RTL exception classes) hold a `string*`.
* **No game code references either segment.** [O] I resolved the NE relocation table of every
  segment. The only references into `11a0`/`11a8` come from segment `1000` (RTL) and two far
  pointers in DGROUP (`31bc`, `31c0`). No game function calls `__InitExceptBlock`, so no game
  function uses `try/catch` or EH-registered destructors.
* **What is reachable at run time** [O]:
  1. `_ExceptInit` (11a0:04e7), called from the program entry point (1000:0006) before `INITTASK`.
  2. `setjmp` (1000:32e5) and `longjmp` (1000:3309) call `xx_GetBCCFrameState` (11a0:34e7),
     `xx_UnwindFrames16` (11a0:18ba) and `xx_UnwindTopFrameToState` (11a0:25b4). Game code uses
     setjmp/longjmp at 1118:0000 and 1140:008c. The EH frame chain is always empty in this program
     (`SS:0014` = FFFFh), so these calls do nothing.
  3. Out of memory: `operator new` (1000:05f1) calls `_new_handler` (DGROUP:3032 → 1000:055c),
     which throws `xalloc` through `_ThrowException` (11a0:1689). `TStringRef` allocation failures
     throw the static `xalloc` at DGROUP:302c through 1000:2151. No catch frame ever exists, so the
     sequence is: `xx_RaiseException16` → no handler → unwind pass → `terminate()` → default
     handler → `abort()` (1000:0186) → `raise(SIGABRT)` → message "Abnormal program termination"
     (DGROUP:2de2) → `_exit(3)`.
* **Port impact: nothing here needs re-implementing.** Use native C++ exceptions, RTTI and
  `std::string`. The only observable behaviour worth keeping is that a fatal out-of-memory or
  uncaught exception terminates the program (originally with the "Abnormal program termination"
  text and exit code 3). If the engine reproduces the game's setjmp/longjmp error recovery
  (1118:0000, 1140:008c; documented by the agents covering those segments), plain
  `setjmp/longjmp` or C++ exceptions are enough. The EH-chain bookkeeping in `longjmp` has nothing
  to do here.

## 3. Data structures (RTL internals, given for reference only)

All of these are little-endian 16-bit structures. "far ptr" means `{u16 offset; u16 selector}`.

### 3.1 SS header words and the per-instance EH context [O]

In the EXE, SS = DS = DGROUP. `1000:2e99` (called from `_ExceptInit`) initialises:

| DGROUP | Type | Meaning |
|---|---|---|
| 0010 | u32 | **Constructed-subobject counter.** Compiled code increments it after every completed constructor and decrements it at the start of every destructor (see 11a8:0000/004d and 11a8:0304/0318). The EH engine snapshots it per frame and uses deltas to destroy partially-built objects |
| 0014 | u16 | Head of the EH registration-frame chain (an SS offset). FFFFh means empty. Set by entry 1000:001b |
| 0016 | far ptr | → EH globals block (`11b8:31b2`) |
| 001a | u16 | FEEDh marker |
| 3658 | far ptr[3] | **Context table** `ctx`: ctx[0] = &SS:0010, ctx[1] (3658+4) = &SS:0014, ctx[2] (3658+8) = &SS:0016. EH globals are therefore reached as `**(ctx+8)` |
| 3672 | u16 | SS for which `3674` is valid |
| 3674 | far ptr | Current `ctx` (= 11b8:3658 in the EXE) |

Every EH routine starts with `if (SS == [3672]) ctx = [3674]; else ctx = 1000:2dae(SS);`. The
`else` branch handles multiple stack segments (DLL mode). It keeps a per-task table pointed to by
`DGROUP:6690`, with capacity `DGROUP:3670` = 30 entries of 6 bytes `{SS, ctx far}`. That branch
never runs in this EXE.

### 3.3 Registration frame (on the stack, built by `__InitExceptBlock`) [O]

A function using EH loads `AX:BX` = far pointer to its context table and calls 11a0:0052. The
frame lives at `BP + (int16)table[+4]`, for example BP-1Eh.

| Off | Type | Meaning |
|---|---|---|
| +00 | u16 | Next frame (the previous chain head) |
| +02 | far fn | Handler, always 11a0:26f3 `_ExceptionHandler` |
| +06 | far ptr | Context table of the function |
| +0A | u16 | Function's SP after the call. Used to restore SP when entering a catch block |
| +0C | u16 | **Current state.** The function body writes the offset of its current context entry here (e.g. `MOV [BP-1Ah],6` / `0Eh` in 11a8:0389) |
| +0E | u16 | SS at entry (`1000:00e5` = `MOV AX,SS; RETF`) |
| +10 | u16 | SI at entry |
| +12 | u16 | 1 while a `__finally` block runs from an unwind (abnormal-termination flag), else 0 |
| +14 | far ptr | Exception record while an `__except` filter or handler runs |
| +18 | u16 | Near ptr to an `{record, context}` pair for the filter |
| +1A | u32 | Snapshot of the counter at SS:0010 |

`__ExitExceptBlock(next)` simply stores `next` back into SS:0014.

### 3.4 Function context table (compiler-emitted, read-only) [O]/[I]

| Off | Meaning |
|---|---|
| +00 | far ptr to the exception-specification list (`throw(...)` types, NULL-terminated far tpid pointers), or NULL |

Entry types (the handler's jump table is at 11a0:2b25, the unwinder's at 11a0:25a8):

| Type | Meaning | Search pass (`_ExceptionHandler`) | Unwind pass (`xx_UnwindLocals`) |
|---|---|---|---|
| 0 | `__finally` / cleanup block | skipped | Call far fn at payload, with frame+12h = 1 |
| 1 | `__except(filter-function)` | Non-C++ exceptions only: call filter (via DGROUP:668a). Result <0 continues execution, 0 continues the search, >0 enters the handler | n/a |
| 2 | `__except(constant)` | Same as type 1, with the constant u16 at payload | n/a |
| 3 | C++ `try` block | C++ exceptions only (code 0EEFFACEh): find a catch (11a0:266a) and enter it | n/a |
| 4 | Catch block in progress | skipped | Destroy and free the exception record whose `(frame, state)` matches (record +24h/+2Ah) |

`{far code address of the catch block; far tpid* catch type, NULL for catch(...); u16 flags; ...}`.

### 3.6 Emulated exception record and dispatch protocol (11a0:1906/17b5/18ba) [O]

* `EXC_RECORD` (on the stack): +00 u32 code (bit 28 cleared); +04 u32 flags (1 = non-continuable,
  2 = unwinding, 4 = exit-unwind; the dispatcher tests `& 6`); +08 u16 nested record; +0A far
  exception address; +0E u16 nParams (≤ 15); +10 far params[15].
* `CONTEXT16`: a snapshot of all registers. It holds 32-bit registers plus FS/GS when the CPU-type
  byte DGROUP:0034 ≥ 3 (386+), and 16-bit registers otherwise. It is used to resume after
  "continue execution".
* Handler call: `int far handler(EXC_RECORD near* rec, u16 frame, CONTEXT16 far* ctx, u32 0)`.
  Returning 0 means continue execution; any other value means continue the search.
* Codes seen: 0EEFFACEh (Borland C++ throw: 3 params {far name, far throw PC, far EXC_REC}),
  C0000025h (non-continuable violation, raised by 1906), 00000026h (default unwind record in 18ba).

### 3.8 Vtable layout (example: `typeinfo`, 11a0:3bcc) [O]

use this header.

## 7. Behaviour narratives

### 7.1 Startup [O]
`entry` (1000:0000) calls `_ExceptInit` (11a0:04e7) first, then `INITTASK`, then sets
`SS:0014 = FFFFh` (1000:001b). `_ExceptInit` records SS in DGROUP:3672 and builds the context
table at DGROUP:3658 (1000:2e99): counter → SS:0010 = 0, chain head → SS:0014 = FFFFh, vars →
SS:0016 = 11b8:31b2, SS:001a = FEEDh. It then points vars+20 at the emergency buffer and stores
DGROUP in 31c4/31c6.

### 7.2 Throw (`_ThrowException` → `xx_ThrowExceptionCore`, 11a0:11e5) [O]
1. vars+06 = DGROUP. vars+1C = &vars+28. Copy the type name (tpid + name offset) into vars+28,
   truncated to 127 characters. vars+1A = line, vars+16 = file.
2. Size = tpid+0. For class types, cflags = tpid+8; for pointers/references, the match type is
   the tpid at +6.
3. r = `xx_AllocExceptRecord(size + 3Ah)`. Push r onto vars+0 and fill the fields of 3.5
   (free function 11a0:09f3, r+38 = 1, r+39 = 0).
4. `memcpy(r+3A, obj, size)`. If cflags bit0 (copy-ctor), call it through 0b7c (counter saved and
   restored around the call).
5. If not a rethrow and cflags bit1 (has dtor), destroy the original object (0ee5, vb = 1).
6. `xx_RaiseException16(0x0EEFFACE, 1 /*non-continuable*/, 3, {far vars+1C, far throwPC, far r})`.

### 7.3 Raise and dispatch (`xx_RaiseException16`, 11a0:1906) [O]
1. Push AX..DI, DS, ES; `sub sp,186h`; call the empty hook 1901.
2. Capture the flags and a CONTEXT16 (32-bit registers via `pushad`/`pushfd` if
   DGROUP:0034 ≥ 3).
3. Build the record: code with bit 28 cleared; flags; nested record = 0. Exception address =
   args[1] for 0EEFFACEh, otherwise the caller's return address. nParams = min(nArgs, 15)
   (0 if args is NULL); copy the params.
4. `r = xx_DispatchException16(&rec, &ctx, FFFFh)`.
   * r == 0 (a handler wants to continue): if the record is non-continuable, replace it with
     {C0000025h, flags 1, no params} and dispatch again. Otherwise restore the registers from the
     context and return to the raiser.
   * r ≠ 0 (nobody handled it): flags |= 2 and dispatch again (unwind pass, so every frame
     destroys its locals). If that returns 0, resume as above. Otherwise call **`terminate()`**.

For C++ throws, a frame that catches never returns to the dispatcher: it far-jumps into the catch
block (7.4). An uncaught C++ exception therefore always ends in `terminate()`.

### 7.4 Per-frame handler (`_ExceptionHandler`, 11a0:26f3) [O]
Inputs: rec, frame, ctx. table = frame+6; funcBP = frame − table[4]; vars+6/+8 = frame+0E/+10.

* **Unwind pass** (rec flags & 6): `xx_UnwindLocals(frame, 0)`. Then, for a C++ exception, check
  the function's exception-specification list (table+0). If it is non-empty and no listed type
  matches (0a7d), unlink this frame (chain head = frame->next), call `unexpected()`, then restore
  the saved chain head. Return 1. (The `throw()` specification is therefore checked as the
  exception leaves the function.)
* **Search pass**: state = frame+0C. While state ≠ 0, read `{next, type}` at table+state and
  dispatch on type (jump table 2b25):
  * 3 (try, C++ exceptions only): entry = `xx_FindCatchHandler(tryblock, r)`. If found: r+24 =
    frame, r+26 = entry, r+2A = state. `xx_UnwindFrames16(frame, rec)` unwinds all inner frames;
    `xx_UnwindLocals(frame, next)`; frame+0C = state; `xx_InitCatchParam(...)`. Then
    `xx_JumpToHandler(entry->code)` with SP = frame+0A, BP = funcBP, DS = frame+0E, SI = frame+10.
  * 1/2 (`__except`, non-C++ exceptions only): frame+14 = rec, frame+18 = &{rec, ctx}. Evaluate
    the filter (call through DGROUP:668a with the function's BP/DS/SI, or use the constant).
    <0: if non-continuable, frame+0C = next; return 0. 0: continue. >0: frame+18 = 0, then unwind
    and jump as for a catch.
  * 0/4/5: skipped.
  * state = next.
* Return 1 (continue search).

### 7.5 Unwinding locals (`xx_UnwindLocals`, 11a0:237e) [O]
For each entry from frame+0C down to the target state: set frame+0C = state, then
* type 0: [6686] = far fn; frame+12 = 1; call it; frame+12 = 0.
* type 4: find the record in the vars+0 list with r+24 == frame and r+2A == state; unlink it;
  `xx_DestroyRecordObjects`; free it via r+1A.
* type 5: `xx_DestroyLocalsList(list, counter delta, frame, funcBP)`.

### 7.6 setjmp / longjmp interplay (segment 1000) [O]
`setjmp` (1000:32e5) stores SS:0014 in jmp_buf+14h and 0 in +16h (after calling 34e7), then
KERNEL `Catch`. `longjmp` (1000:3309):
* If SS:0014 ≠ saved: `xx_UnwindFrames16(saved, NULL)`, then SS:0014 = saved.
* If the saved frame is a BCC frame whose state ≠ jmp_buf+16h: `xx_UnwindTopFrameToState`.
* Force a non-zero return value, then KERNEL `Throw`.

Because the chain is always empty in this program, only `Catch`/`Throw` matter in practice.

### 7.7 String growth rule (`string::round_capacity` and `TStringRef::splice`) [O]
With the defaults (initial 63, increment 64, freeboard 63) the formula reduces to
`(nc / 64) * 64 + 63`. So nc 0..63 gives capacity 63, 64..127 gives 127, 128..191 gives 191, and
so on. A buffer of capacity+1 bytes is allocated for the NUL.

`splice(start, extent, dat, n)`:
1. newLen = nchars + n − extent; nc = round_capacity(newLen).
2. If nc > capacity: `grow_to(nc)` (realloc in place).
3. Else if capacity − nc > freeboard and flags bit0 is clear: allocate a new buffer of nc+1, copy
   the first `start` bytes into it, capacity = nc. Quirk [O, 11a8:08e1-08ef]: the out-of-memory
   test after this `malloc` checks the *old* `array` pointer, not the new buffer, so a failed
   allocation here is not detected. `reserve` (06f6) and `check_freeboard` (0764) also store the
   `realloc` result without testing it. Only `grow_to` (07cc) and the constructor (05ae) test the
   new pointer and throw `xalloc`. None of this matters to the port.
4. memmove the tail (`nchars − start − extent` bytes) to start+n. Fill [start, start+n) from dat,
   or with spaces (20h) if dat is NULL. nchars = newLen; NUL-terminate. If a new buffer was
   used, free the old one and switch.

This module does not use the static options `case_sensitive`, `paranoid_check` and `skip_white`
except through their setters.

## 9. Open questions

1. The exact Borland RTL names of the internal helpers (`xx_*`) are unknown. The public names
   (`__InitExceptBlock`, `_ThrowException`, `_ReThrowException`, `_CatchCleanup`,
   `__DynamicCast`, `__GetTypeInfo`, `__GetPolymorphicDTC`, `__isSameTypeID`, `__Throw*`) follow
   Borland conventions, but no symbol table confirms them. `__TypeIDName`,
   `TStringRef::check_freeboard`/`grow_to` and the `typeinfo` copy-ctor/`operator=` attributions
   are inferred from behaviour.
2. The meaning of the third `_ThrowException` argument (stored at record +08 and passed to the
   type-match helpers). All callers in this EXE pass 0.
3. The full semantics of the calling-convention mask in 0b7c/0ee5/10ac. Every descriptor in this
   EXE uses mask 5, and the branch where bit 2 is set without bit 100h produces a selector ≥ 20h
   that matches no case. I did not resolve this because nothing in the game depends on it.
4. In `setjmp` (1000:32e5), the result of `xx_GetBCCFrameState` is discarded and jmp_buf+16h is
   always set to 0. This looks harmless in this program but could be a deliberate Borland quirk.
   The segment-1000 owner may want to confirm it.
5. The 4 bytes at EH_VARS+24 and the payload layouts of context entry types 0, 4 and 5 beyond
   what `xx_UnwindLocals` reads were not fully decoded. No game code emits these tables.
6. Whether the game ever installs its own `new_handler` or terminate handler, which would change
   the out-of-memory path in 1. Nothing in 11a0/11a8 does, and `set_terminate`/`set_unexpected`
   have no callers.
